## 1. 先确定这次设计什么

用户希望它有自己的性格，不讨好，十分宜人，有兴趣，也会照顾使用者——以亲密伴侣的关系感理解这份体贴。当前番茄钟主要通过生活场景、有限动作、触碰和文字表达，无法凭这些输入准确理解使用者的内心。

本轮建议把屏幕上的人物收敛为：**爱试一点小花样，做成了有点小得意，对你亲近而大方。** 这是三种可见表现，不是新增三个并列人格标签：小得意是它享受自己选择的反应。认真但不较劲继续约束做事方式；笨拙只偶尔出现。进一步的主次关系、场景写法和复盘见[创作框架](20-character-framework.md)。

“有冲击力”在这里指第一次接触就能看出一点特别之处，例如小小的积木作品被它认真对待，或者它享用自己的茶时也给你留了一杯。不以更多运动、更多气泡、更响的声音或必须追看的情节制造存在感。

本轮只做文稿与代码对照、情境推演和取舍，没有新增互联网研究、制作新画面、运行交互原型或做用户测试。核对应用基线为 `6835f5b54433967aee8ff671184acb8ce8bf5672`，现状入口见[代码地图](../CODE_MAP.md)。

## 2. 用户实际能做什么

下表按操作含义归组，不把每个按钮都做成一条剧情。触屏、鼠标、键盘是同一功能的不同输入方式；手机上的角色设计不能依赖鼠标悬停。

| 交互形式 | 当前已有的具体操作 | 人物可以借此表达什么 | 不应据此推断什么 |
| --- | --- | --- | --- |
| 打开、返回、切页 | 进入 App，在专注与记录之间切换，从隐藏状态回来 | 在合适入口自然呈现当前生活；恢复真实状态 | 打开不等于想聊天；返回不等于孤独或想念 |
| 准备计时 | 点数字打开时长尺，调整并应用时长，选择短／长休息 | 准备态可以有安定的生活姿态 | 选长时间不表示更认真、更值得亲近；不增加鼓掌 |
| 控制计时 | 开始、暂停、继续、确认结束，开始休息、准备下一段 | 准备、投入、停驻与收尾；停止时善意稳定 | 暂停不等于累了，提前结束不等于失败 |
| 直接触碰角色 | 点按身体／头部区域、手或柔软部位；已有摸摸、击掌、轻压回弹；键盘可触发摸摸 | 短暂、明确的亲近回应，之后回到原有事情 | 不把次数当亲密度；不要求长按、连点或精准手势来换更好的回应 |
| 主动请求一句话 | 求鼓励、换一句、切换已有类别、收藏、关闭 | 用自己的口吻回应明确请求 | 所选类别不是对用户心理状态的诊断；关闭不表示拒绝关系 |
| 记录想法 | 留标记、写意图／想法、编辑、保存、删除及撤销 | 让出阅读和输入空间，真实报告保存结果 | 不分析私密文本来猜心情、改剧情或装作懂用户 |
| 看记录 | 四个书签切章，翻页／滑动，点开手记、想法、收藏话语、欢迎笺，按日期或文本查找 | 可选回看实际留下的片段 | 翻到哪页不证明记得哪段剧情；书本翻页不是角色当下在翻书 |
| 点小屋的图片索引 | 进入某类活动的已保存来源记录 | 查找真实共同经历 | 当前不是任意家具互动、换装、装修或领取故事物件 |
| 调整偏好 | 声音与试听、动画、场景变化、鼓励等开关，以及常用时长 | 尊重用户选择，静态与安静时仍保留人物含义 | 关闭动画或鼓励不降低亲近、不触发失落 |
| 收起／唤回工具卡 | 运行中工具卡按现有规则退让；点把手或空白处唤回 | 留出观看与专注空间 | 这是布局行为，不是角色懂得读心；不挪动正在操作的目标 |

依据：[专注界面](../../src/screens/HomeScreen.tsx)、[触碰](../../src/hooks/companion/useBlueCompanionTouch.ts)、[触碰形变](../../src/logic/blue-touch.ts)、[记录导航](../../src/hooks/records/useBookNavigation.ts)、[记录章节](../../src/components/records/book/BookChapters.tsx)、[设置](../../src/screens/SettingsScreen.tsx)。

**自动发生的事另算。** 倒计时推进、自然到期、保存结果、系统减少动态偏好、设备昼夜时间与页面隐藏都是系统事实。它们不是新的用户表达。计时可以推动本段的合法活动状态，动画结束本身不写入事实；时间经过也不证明用户一直看着或一直专注。

## 3. 角色实际能用什么表达

| 表达通道 | 当前具备的基础 | 本轮允许依托的设计 | 状态与成本说明 |
| --- | --- | --- | --- |
| 固定场景与静态物件 | 果园、室内／露台、十一项活动及各自道具 | 把偏好放在姿态、物件用途和结果构图里 | 通道已有；新摆法仍要核对构图、接触与状态 |
| 有限身体表达 | 视线、表情、头身姿态、短臂、呼吸等 | 一次可读的回应或有来由的短动作 | 不依赖精细手指、远距离伸手、复杂走位与连续演技 |
| 用户触碰后的反馈 | 摸摸、击掌、轻压与回弹 | 有回应，然后自然回到自己的活动 | 不增加连续点击任务；减少动态时有静态反馈 |
| 本段活动进展 | 既有活动随会话时间呈现进展，支持暂停与结果驻留 | 开场、过程、结果可以讲一件很小的事 | 现有活动动画不是完整 DAY 故事系统，不假称长期剧情已实现 |
| 气泡与文字阅读 | 鼓励、功能状态及现有阅读入口 | 一句表达当前意愿、偏好或“这件事也想到你” | 新日常台词的宿主和触发尚未实现；不能直接混入鼓励轮换或每次 tick 自动播放 |
| 已保存的图文记录 | 专注／休息纪念画、手记、收藏与来源索引 | 让用户主动回看发生过的事 | 当前纪念画按既有活动呈现；新剧情变体需要对应内容身份与准确快照，不能靠改画冒充记忆 |
| 声音 | 可选计时提示与试听 | 保持功能提示 | 本期不依赖配音表达性格，不把提示音扩成角色说话 |

首期场景提案依托这些通道即可。**唯一值得保留的轻扩展候选，是“点一个场景物件，得到一次短回应”**，具体见下方纸船卡。它目前没有实现，必须额外处理触碰目标、合法时机和取消；先不加拖拽道具、自由对话、分支问答、喂养、回礼或小游戏。

角色不知道用户是否真的在看屏幕，不知道沉默的原因，也没有已实现的爱好学习系统。摄像头、麦克风、眼动和情绪推断不在本方案内。背景故事可以帮助作者写一致，但不能替代屏幕上的证据。

## 4. 性格做减法：保留、转译和放下

本表是针对当前展示条件的创作建议；不将新提法追认成用户已批准的正式性格。原有已确认基准仍见[性格简历](10-character.md)。

| 原有想法 | 本轮处理 | 屏幕上怎样证实 |
| --- | --- | --- |
| 好奇、有自己的小主意 | 合并为首要表现：**爱试一点小花样** | 同一套普通东西，留下一个自己的选择；如积木搭得不高，也要有喜欢的小旗 |
| 小得意 | 作为醒目的辅助表现，不另列主性格：**做成了会自己欣赏** | 小作品已经清楚存在，角色满意地看着或给一个简短反应；不等用户夸 |
| 宜人、关心使用者 | 转译为关系表现：**亲近大方，愿意分享** | 点它有明确回应；自己的生活里偶尔也给你留一份；分享后无需回答 |
| 认真但不较劲 | 保留为行为底线，不另加成长任务 | 做事有因果，自己处理小调整；可以自然暂停、享受结果和结束 |
| 轻微笨拙 | 保留为少量变化，暂不独立制作专门段子 | 仅在已有画面能读出时使用；穿模、悬空、忘记保存不是性格 |
| 兴趣很多 | 作为题材范围，不再当人格证据 | 十一项活动继续可用；重复的选择方式让它们属于同一个角色 |
| 恋旧、复杂偏好、某项专业技能 | 暂不作为核心卖点 | 若以后有真实的重复使用和具体选择再写，不先补一大段设定 |
| 越来越懂用户内心、能察觉没说出的需要 | 从当前主弧光中放下 | 现有输入不足以支持；仅回应真实操作和明确请求 |
| 创伤治愈、误会和解、长期学习怎样爱人 | 不投入当前剧情制作 | 需要连续阅读、对话和大量前情，容易成为只存在于文稿里的深度 |
| 地图、木箱、选择小屋的过去 | 保留为可选作者资料 | 不要求用户阅读、不自动新增素材；它们不承担当前角色辨识度 |

三项表现是一组内容要覆盖的方向，不是每个场景都必须演一次。不是每项活动都搞发明，不是每次成功都邀功，也不是每次泡茶都给用户送一杯。

“有个性”由它自己的兴趣、选择和享受来表现，不靠拒绝暂停、故意不回应或惩罚用户来证明。亲近从第一次使用就可以存在，不以时长、回访或收藏数量升级。

## 5. 怎样从有限形式里产生趣味

最值得优先试的趣味有三种：**普通物件有一点出乎意料的用法；很小的一件事被它认真喜欢；正在过自己的生活，却自然想到你。** 它们都可以把主要意思留在最终画面里。

重要含义需要停得住，额外小表演可以错过。积木与小旗始终在那儿，小得意的一眼可以短暂出现；给你留下的杯子可以保留，点头不必补播。不能因为用户没看见动作就丢结果，也不把表演做成每隔几秒必须出现的刺激。

有限的台词优先说明画面不容易表达的意愿和关系：“这杯给你”比解释“我泡好了两杯茶”更有用。台词只作候选，不追求句句笑话，不靠给物件强行拟人制造机灵。看到当前画面就应读懂，不要求用户记得上一句。

## 6. 四张场景卡，从现有入口出发

以下是审稿与原型范围，不替换 F 场景或正式 DAY 章稿。前三张不需要新增用户操作，但均可能需要内容、姿态或图稿工作；第四张需要新增一次物件点击，是后续候选。完整交付仍须按[章稿模板](12-stories.md#chapter-brief)处理各时长、每个停止落点、重复稿与保存。

### APP-S01 · 不高，也要有旗：先让它有意思

- **入口与已知事实：** 本段已有 F7 积木题材；开始时是明确的小建造目标，只有实际呈现到相应结果才显示完成态。
- **人物选择：** 沿用现有低矮积木构图与带旗的积木。作品不求大，但它喜欢让这面小旗留在顶上，也会欣赏这个结果。不要求用户帮忙。
- **画面与落点：** 起点是现有待摆的积木；结果是小小的积木搭建和旗。趣味来自事情很小，它仍愿意按自己的心意认真对待。旗随原有积木连续移动，不新增一次凭空取旗、插旗的表演。
- **用户操作：** 普通开始、暂停、结束与既有触碰。没有拼搭、解谜或点亮奖励按钮。
- **文字：** 可无台词；候选“就这么高。旗子得有。”表达它自己的取舍，不替画面命名成看不出的建筑。若去掉文字只能读出普通搭建，就只能说明活动可读，尚不能认定人物特点已表现充分。
- **制作账：** 本轮复盘后放弃首稿的小城堡改造，优先检验既有构图中的人物选择与满意回应。若仍需调整摆放或姿态，要核对支撑、手臂路径、遮挡及过程状态；复用道具不等于零制作成本。新台词入口另计，不能混入现有鼓励触发。
- **打断与重复：** 提前结束只呈现实际已放好的部分，不突然补完。再次做是新的独立搭建，不重复声称第一次成功，不要求每次升级规模。

### APP-S02 · 给你留一杯：让体贴有明确对象

- **入口与已知事实：** 茶的独立短稿提案。起点就有两杯已泡好的茶，避免把未演到的第二次冲泡凭空算作完成；这不是现有单杯 F4 的既成事实。
- **人物选择：** 它自己要喝茶，也愿意给你留一杯。把一杯安放在桌上朝向用户的一侧，自己拿起另一杯。
- **画面与落点：** 同一张桌、两个杯子；一杯放好、一杯由它享用。候选“这杯给你。”说明关系，随后画面可以安静保留。
- **用户操作：** 不需要领取、接杯、道谢或等茶凉。点击角色仍走原有回应，不把每个杯子做成按钮。
- **制作账：** 新增第二杯的初末态，并核对一次短距离放杯与原有持杯。可先用固定机位的状态图验证；若手物接触说不清，缩为两杯已经安放好的休息片段，明确只是关系片段，不包装成完整泡茶故事。
- **打断与重复：** 未安放到位就停止时，不说已给你放好。这个场景偶尔使用；普通单杯喝茶仍然成立，不把全部生活改成服务使用者。

### APP-S03 · 正在读书，接住你的触碰：让自主与亲近同时存在

- **入口与已知事实：** 已有 F3 阅读场景，用户真的点了角色的可触碰区域；不是检测到用户目光。
- **人物选择：** 它正在投入自己的阅读，短暂回应这次接触，再回到书上。动作可以沿用现有温和触碰反馈，先检验场景中的一致性。
- **画面与落点：** 回应前后都是同一本书和相同的真实进度；不为给出表情重置阅读动作，不把书变成凭空消失的道具。
- **用户操作：** 点一下已有触碰区域，回应自动结束。原来计时继续；不新增等候、不要求连点，也不提高互动次数奖励。
- **文字与制作账：** 默认无台词。先用已有回应，不追加举书遮脸、探头、放书、挥手的一整套演出；确需改手势时重新核对握持。
- **人物作用：** 这张卡承担相处方式，不独立算新剧情，也不能单凭这一张证明它有玩心。清楚回应、回到自己的兴趣，两者一起成立。

### APP-S04 · 再拨一下纸船：仅保留一个轻互动扩展

- **状态：** 暂不实施。前三张成立后，再判断是否需要这个新入口。
- **入口与已知事实：** 结果驻留时，盘中已有合法存在的船，且没有面板、确认或操作需要优先处理。不能在纸船尚未放入水中时把它变出来。
- **用户操作与角色行动：** 点一次盘子范围，伙伴轻拨一下水，船沿预设短路径转向或移动，然后停住。主体是一处点击、一次回应，不是水流模拟、划船游戏或连续点击挑战。
- **制作账：** 需要新的可访问点击目标、手物接触动作、船的连续路径、减少动态替代，以及重复输入／离开时的取消规则。虽然复用纸船，也比前三张多一类交互工作。
- **边界：** 不增加进度、奖励或收集，不写成新一次造船；不把点了物件当成用户偏好。反复点击不能排队叠加动作，不能遮住控件；若小屏放不下清楚的目标，放弃这张。
- **静态版本：** 可用一个短暂、可理解的朝向状态替代路径运动，回应后保持物件连续；不能把“开启动画”设为享受内容的条件。

**首轮只建议原型化 S01、S02、S03。** 它们分别验证“自己的趣味”“主动想到你”“对真实互动的回应”。静态概念稿可先各用两幅状态图和至多一句候选台词，但正式实现仍遵守完整章稿与安全中间状态要求；两幅概念图不等于完整状态设计。S04是明确标价的备选，不借“好玩”顺手加玩法。

## 7. 哪些场景不值得做，以及为什么

| 方案 | 淘汰或暂缓的具体原因 | 保留下来的较小表达 |
| --- | --- | --- |
| 一段委屈、误会、解释、和解 | 要读连续对白，也依赖用户回应；容易给暂停、离开附上关系含义 | 一次明确温和的回应，或一句诚实的当下意愿 |
| 倒茶失手、接住杯子、擦水、害羞地笑 | 关键趣味全在连续表演，手臂接触成本高；错过瞬间只剩普通画面 | 杯子安稳放好；笨拙另找已有构图能表达的一小处 |
| 出门探险、多场景遇人、带回纪念品 | 新场景与角色成本高；容易假称后台发生了事或带回物件 | 同一空间里的纸船、书、窗景；往事留作可选背景资料 |
| 记得用户昨夜难过、猜到现在疲惫 | 缺可靠输入，温柔台词会变成无依据判断 | 根据明确的休息选择或主动鼓励请求回应 |
| 先前怕失败，后来被用户治愈 | 要长期前情；与已确认的不较劲和自主生活不合 | 一次自己处理的小调整，之后继续享受自己的事 |
| 用户拖道具帮助完成，或选答案改变结局 | 加操作负担、分支和保存成本；容易使番茄钟变成任务游戏 | 先只看它自己的小尝试；最多保留一次可选的局部物件回应 |
| 每项活动都送礼、邀功、问“喜欢吗” | 亲近变成持续索取回应，人物自己的趣味被冲淡 | 自己享受、回应、分享、照顾交错出现，无需用户配合 |
| 只在背景里写深情、勇敢、复杂经历 | 用户在 App 中没有证据，增加设定却不增加体验 | 从一个看得见的选择开始，不能表达就不作为当前卖点 |

## 8. 人物弧光的范围也随之收缩

当前最适合的是**稳定性格，加上一次次完整的小事**。一次故事可以从一个小主意走到可见结果，也可以从尝试走到换个做法；变化发生在具体选择里，不要求每次得出道理。

关系从第一次就亲近，后续通过真实留下的经历增加熟悉感。当前不做“用户越努力，它越爱用户”或“逐渐学会读懂用户”的阶段成长。动画、彩蛋、文字被看过多少，都不能证明亲密程度。

宏大的传记和长期心理转变先退出首期制作范围。现有[背景故事](17-character-background.md)仍可供作者保持一致，但用户完全不读也应能认出这个角色。待几张简单场景真正有吸引力，再考虑少量有可靠前情的后续变化。

## 9. 十个角度的文稿复核与取舍

以下记录本轮情境推演的结论，不是十轮用户测试，也不是新互联网研究。每一项都用于删掉表达不了、成本过大或影响专注的设计。

| 检查角度 | 本轮收紧的地方 |
| --- | --- |
| 可用入口 | 先列真实操作；没有自由对话，就不把多轮沟通写成主要弧光 |
| 人物辨识度 | 爱好数量不算性格；把核心收敛到玩心、小得意、亲近分享 |
| 小屏可读性 | 微表情和精细手势不独自承担含义；放弃需要额外解释的小城堡，先用已有积木与旗 |
| 错过中间 | 作品、杯子等主要意义留在可停驻画面里；短暂趣味可以错过 |
| 静音与减少动态 | 先看状态与文字是否成立；不把动画偏好变成内容等级 |
| 完全不互动 | 伙伴仍有事可做、也能自己满意；彩蛋不是获得完整体验的必需步骤 |
| 反复使用与连点 | 不每次宣布第一次成功，不靠稀有奖励维持兴趣，不积压重复回应 |
| 随时停止 | 未完成保持真实落点，不因它正在送东西阻止退出，不生成待办 |
| 亲近是否有对象 | “两杯茶”必要时用一句话说明给谁；同时保留自己也享用的生活动机 |
| 制作与事实成本 | 第二只杯子、积木重摆和点击纸船分别记成本；未来新故事不能冒充现有纪念画能力 |

本轮最重要的删减是：不再用“越来越懂你”“丰富身世”“兴趣很多”承担主吸引力；不为了笨拙制作复杂事故；不把每次工具操作写成情感戏。保留下来的场景仍须通过实际画面检验，不能因为规则合格就宣称好玩。

## 10. 下一步如何检验

先用同一角色、同一画风做 S01—S03 的小稿，不增加页面或复杂交互。查看者不知道设定也应能回答：它在做什么；哪里像它自己的选择；哪处让我感到它在回应或关心我。每张只负责其中一个重点，一组稿覆盖三个问题。

分别看完整稿、只看结果、去掉可选台词、关闭动作，以及重复看几次。如果删掉一句话只损失某个具体意图，不必判失败；如果整个人格都消失，说明太依赖文案。若只看见一个普通活动，检查选择与结果；若需要不停点才能有意思，删掉交互负担。

合格的下一步交付是“有画面证据的小场景”，不是继续扩写传记。先由用户评稿，再用少量目标使用者做定性试看；吸引力、长期耐看和实际制作投入目前均未验证。

## 11. 事实、保存与发布边界

本稿不改计时、输入、鼓励和收藏的现有规则。手动结束仍保留短章小记，自然到期保留完整章页；未来故事收集仍须自然到期、作者定义的完整结果且保存成功。完整的一分钟短稿同样适用，轻触与彩蛋不增加资格。

当前专注／休息活动的纪念画可来自已保存的手动或到期记录，与未来故事成果不同。本稿的新杯子、城堡构图、文字与船的互动还不是已保存的历史；接入时必须同时说明当前态、结束落点、内容版本和可还原的记录，不把它们只作为覆盖旧记录的图片替换。

本轮只更新讨论文档和入口。没有更改应用、增加性格数值、调整场景抽选、实现对象点击或开放新文字触发。正式采纳时再更新对应性格正文、章稿、功能与验收，依照当前[成本规则](12-stories.md#scene-cost)确定制作范围。
