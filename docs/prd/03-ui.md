### B.1 整体 UI 硬性规范

本节是专注、记录、设置及临时面板共用的执行要求；页面章节只写差异，绘画另见[B.4.1](#drawing-rules)。两处主导航为「专注」「记录」，低频设置从专注页固定入口打开，关闭回专注，最多三个主要界面。

**稳定的比较条件：同一页面、同一可用视口、同一字号与缩放设置。** 普通反馈和状态切换不得推动布局；用户主动展开记录、加载历史等内容变化按各页规则保留阅读锚点，不要求整份历史固定高度。视口或字号改变时，按 LAY-04 重新排布。

| --- | --- | --- |

| LAY-06 色彩与可读性 | 功能文字与背景对比至少4.5:1；识别控件、选中状态及焦点所必需的图形与相邻背景至少3:1。成功、失败、选择和暂停不能只用颜色区分。绘画保留主蓝色与适度明艳感，必要时给文字加稳定承托底，不靠把整幅画变白解决可读性。 | [T-LAY06](07-acceptance.md#t-lay06) |
| LAY-07 焦点与反馈 | 普通提示不抢焦点，关键状态可被读屏获知，倒计时不逐秒播报；图表有文字等价数据。模态面板打开时焦点进入，键盘循环限于面板，背景不可操作；提供关闭／取消，Esc按当前任务返回或关闭（鼓励选择态依A.4.1），退出面板后回原入口或当前合理位置。普通气泡不作模态；退出是否留草稿或等待已受理结果依[B.1.1](#ui-command-lifecycle)。 | [T-LAY07](07-acceptance.md#t-lay07) |
| LAY-08 装饰让位 | 场景不遮读数、不拦截输入、不移动真实按钮。遵循系统减少动态或用户关闭动态的选择，以静姿保留状态；关闭场景仍可完成全部核心操作。非必要的持续或循环动效可关闭，停止装饰不暂停计时、不改变所得；注意力调度见[B.4](#attention-policy)。 | [T-LAY08](07-acceptance.md#t-lay08) |
| LAY-09 重要内容不遮挡 | 同屏陪伴时，短气泡、主动鼓励与控件不得遮住角色面部识别区（双眼、嘴部与辨识轮廓）或当前关键动作；角色也不遮计时与操作。按实际素材和动作范围预留空间，不能只验静止图。空间不足时切同层阅读布局，可让场景暂退场，保留简短计时状态，不留一张被面板截断的脸、不撑长背景页。底部抽屉打开时，伙伴保持原大小、上移到抽屉上沿露出整张脸；时间下方放不下就暂时退场。 | [T-LAY09](07-acceptance.md#t-lay09) |
| LAY-10 操作按任务分组 | 同一对象的主次操作保持可辨的空间归属。暂停／继续与结束组成计时控制组，鼓励与想法工具在其下另成一行；结束始终可直接找到，计时中卡片[让位](02-features.md#focus-step-aside)时一次呼出即可到达。次级只降低视觉权重，不降低可发现性、对比和触区，不混入无关工具文字行。位置关系见A.1.2。 | [T-LAY10](07-acceptance.md#t-lay10) |

<a id="ui-command-lifecycle"></a>

#### B.1.1 动作生命周期与局部反馈

每个动作按“尚未受理 → 已受理且待确认 → 已提交／冲突／失败／结果未知”呈现自己的状态，不把这些合并成整页锁定。状态由原命令和目标决定，文字、按钮样式可以调整；正式事实及事务仍依数据规格（附录C）。

| 情境 | 界面职责与不变边界 |
| --- | --- |
| 点击、键盘或读屏激活 | 共用一个业务入口；同一激活不重复执行，按下到抬起控件身份改变即取消旧激活。程序性聚焦／组件重建不模拟用户确认 |
| 输入、换行、选字、失焦 | 区分准备值、设置编辑值、可恢复草稿和正式条目；不以回车／收键盘通用提交。非法输入留可修改状态，不改成旧值假称已保存 |
| 请求在途、成功晚到 | 展示局部处理状态；只更新匹配对象／操作的等待。用户已经换对象或继续输入时，不强制关当前面板、不跳原返回页、不抹掉新文字 |
| 关闭、系统返回或取消 | 未受理可取消；已受理结果继续核对，关闭不等于数据库回滚。安全留草稿时无需重复确认，真实冲突／放弃／风险才请求必要决定 |
| 同目标依赖动作 | 局部保护或明确等待原结果，不依旧状态发反向命令；导航、阅读及独立可用操作仍可达。既有错误不能被不相关成功替换 |
| 展示与系统约束 | 声音能力、系统减少动态与用户偏好分开；试听、换鼓励、触摸和关闭提示不写用户行为事实、不推进故事 |

所有成功、失败、撤销提示均绑定原对象；读屏与焦点反馈遵循同一来源，不重复播报每秒变化或把已删除内容作为可操作项。输入／查询／文件作用域模型仅为参考，真实设备、事件序列和跨窗口行为必须执行[D.22](07-acceptance.md#frontend-db-tests)。

<a id="ui-size-contract"></a>

#### B.1.2 尺寸参数与交付要求

**已定的是稳定性与适配规则；计时窗口的具体宽高、比例、最小／最大尺寸和数字字号仍待界面稿确认。** 不从旧圆盘实现或网络示例推定产品尺寸，也不要求所有屏幕使用同一像素大小。

设计与开发共用一份尺寸表，注明视口宽高、字号和缩放条件，并列出：计时区外框与数字字号；反馈预留区；主控与导航的触区和间距；临时面板最大高度及滚动区域；角色面部／关键动作保护范围与文字区域的相对位置。每项写实际数值或明确的自适应规则，不只交一张截图。覆盖320／375／430 CSS像素宽度、所选最短可用高度与横屏；再核验200%文字和键盘状态。条件相同时各状态叠图对齐，条件改变时按 LAY-04 调整。参数未确认只可标为试做默认，不标为设计已定或验收通过。

### B.3 面板、反馈与跨控件约束

| 面板／事件 | 控件关系与返回 | 不可混淆的结果 |
| --- | --- | --- |
| 长文／确认／说明 | 由A.1.2—A.6.1各入口打开，一次一层；后续确认在当前面板切换内容，保留必要返回路径 | 模态只限制当前交互，不暂停会话；关闭退出面板，系统返回／Esc按当前任务返回或关闭（鼓励选择态见A.4.1），均不得绕过输入保护 |
| 重试保存、重试读取、核对未知、关闭提示（ACT-D01、ACT-D02） | 就近说明对象与问题；重试指向原操作或当前读取范围，不能用一个通用按钮替所有对象处理 | 未收到回执不等于失败；关闭／稍后不删待存副本、不清未解决错误，也不声称修复 |
| 节点、到期、后台重返、跨窗口、初始化（ACT-E01—E05） | 属于系统事件，没有独立按钮；按3／4章核对事实，更新对应读数、记录、状态和可用动作 | 不抢当前输入、阅读或确认；不因面板关闭补播；首次初始化须证实空库，失败不冒充新用户 |

**面板切换先保护当前任务。** 由输入转去鼓励、调时或其他输入时，先按A.2处理同一草稿：可安全恢复就保留，不额外索要确认；存在冲突、需要放弃或另写时，在当前层完成必要决定后才切换。保存仍在途时可以关闭，但不能用关闭撤销已受理操作，也不能让旧成功关闭后来打开的面板。读取／保存错误不强制打开新层。抽屉打开时背景不可操作：转去别的任务或切页须先关闭抽屉，草稿照常保留，可从原入口或记录页的“继续草稿”接着写。确认结束期间自然到期，原结束按钮立即失效，当前层原位说明已结束并提供返回；不得把它直接换成可误触的下一段启动。

**所有控件共用三条判断。** 当前状态不适用或尚未启用的入口不伪装可点，隐藏后不留可聚焦热区；本来可用但暂受校验、只读或在途结果限制的动作保留可解释状态，只限制相关动作；等待／失败／成功均绑定原对象，不能互相顶掉。已有文本和真实状态变化按B.1.1及数据规格（附录C）保护，不用全页禁用解决局部问题。

功能核对从本节进入[F动作索引](13-actions.md#act-a)与[C.11字段映射](06-data-commands.md#action-field-matrix)，页面路径验收见[D.26](07-acceptance.md#page-control-tests)，尺寸、焦点与可访问性仍统一按[D.25](07-acceptance.md#ui-layout-tests)。

### B.4 场景、按钮与绘画

<a id="attention-policy"></a>

**注意力调度。** 便签输入、结束确认、数据恢复处理、主动阅读鼓励或历史时，无关叙事动作让位为当前可信静姿；必要状态和错误仍可见，焦点不被夺走。计时与故事事实照常按原规则变化；退出这些操作后显示最新落点，不排队补播。角色触摸只给当次局部回应，不据此追加剧情或催用户继续玩。此规则统筹文字与动作，不新增一套奖励或计时状态。

计时主控使用稳定承托面，与小屋的窗台或桌沿形成可信空间关系；人物、物件、光向、遮挡和接触阴影一致。装饰不设置未定义的隐藏热区，真实按钮不被搬动。动作只占自然需要的几秒，大部分时间静止，一次最多一个叙事动作；新操作取消过时表演，计时不等待动作。静音、静态及隐藏场景时，功能与事实完整。实际稿同时满足“属于同一空间”和“首次用户直接找到暂停”。

<a id="drawing-rules"></a>

#### B.4.1 绘画规则

**最终已确认方向：有卡通趣味的写意水墨，温柔、有意境，带一点明艳感。** 当前功能原型继续沿用既有rough.js绘制方案和圆润蓝色伙伴，先验证交互与动作；工具名称不等于视觉风格。原型可用不表示已达到最终水墨验收，也不自动取消最终方向。

1. **统一画法。** 人物、家具、植物、建筑及现代物品共用笔墨语言；水墨的意境来自用笔、虚实与留白，题材不限于山水、竹窗或喝茶，不以水彩晕染替代。
2. **造型有趣。** 抓住辨识特征，概括圆润的大形；比例、表情和动作可适度夸张，体现伙伴自己的兴趣与选择，不固定为同一姿势。
3. **笔墨有轻重。** 线与墨块结合，用粗细、干湿、断续塑形；物件轮廓轻于主角，浓墨留给神态、关键结构与接触处。柔和靠边缘取舍，避免整圈粗黑边或全图模糊。
4. **配色有主次。** 插画中主角以清亮、鲜明的蓝色为主体，最易被辨认；环境用较浅的嫩绿、鹅黄与少量暖橘衬托。物件有适量完整设色，保留明艳生气，避免全蓝、灰暗或大面积空白躯体；纸底浅暖、干净。
5. **人物长在空间里。** 人物与环境共用笔触、色彩呼应和光向；用遮挡、接触与轻阴影交代位置。脸、手和正在使用的物件清楚，远景疏淡，留白承接空间与界面；计时和操作始终易读易找，纹理不持续流动抢注意力。

画法参考：[六物彩墨轻柔勾勒](https://chatgpt.com/library?file_id=libfile_b056a3673d108191a1c50a88b144d041&account_id=personal)。具体色值、角色定稿与分镜随样稿核验；示例道具不扩大上线范围。验证见[D.4](07-acceptance.md#test-visual)。

**连续动作的身体一致性。** 拿起、移动、停留、放下以及任意中途暂停／结束都要核对手臂、握点、道具支撑与肩部连接；不能只看首尾姿态。允许有意图的卡通夸张，但避免无意的肢体突变、穿透或悬空。够不着时优先调整道具位置、动作路径和身体姿态。算法与数值回归阈值由工程验证维护，不写成永久美术比例。

### B.5 文字、反馈与辅助表达

**入口说清动作和对象，状态说当前事实，结果只说已经确认的事。** 同一功能在入口、面板、结果和记录中沿用同一称呼；图标配可辨名称，辅助功能名称与可见动作一致。选择“25分钟”只选择，“开始专注”才执行；“记录”导航、写新想法、补指定记号和回看本段想法不能共用同一含糊标签。**本版按钮名称已定稿**，可见文字、读屏名称及实现统一使用[B.6](#ui-copy-catalog)；E.9只处理未覆盖的新状态，不自行恢复旧标签。

<a id="feedback-lifecycle"></a>

#### B.5.1 动态文字的职责与寿命

| 类别 | 出现位置与触发 | 保留、替换和退出 |
| --- | --- | --- |
| 状态与时间 | 固定状态位，随真实会话／数据状态更新 | 原位替换；数字不跳宽；倒计时不逐秒播报 |
| 普通操作结果 | 当前对象的预留反馈位，如“想法已保存” | 仅匹配成功后出现；可在下一相关动作或关闭时退出，不堆成消息列表 |
| 自动节点回应 | 固定陪伴位，满足E.2事实与降噪条件 | 可以省略、替换或关闭，不定时轮播、不排队补播；不与功能结果重复说两遍 |
| 主动鼓励／长文 | 用户主动打开的同层阅读区 | 保留到用户换句、关闭或明确切换任务；读到一半不被自动成功、节点或无关错误替换 |
| 校验、待存、失败或未知 | 相关字段／任务面板内；跨页问题另有可找回的稳定状态入口 | 说明对象与可执行下一步；未解决不自动消失为正常，关闭详情不等于解决；不抢输入焦点 |
| 撤销、重试等带动作反馈 | 对应对象附近，沿用预留区域 | 在真实有效期内保留可操作机会；若短提示退出，必须仍有可达的同对象入口；不延长或伪造资格 |

**优先级先看归属，再看严重程度。** 同一位置由当前未解决错误／未知、处理中、已确认结果到可选鼓励依次让位；不同对象的失败不能被另一个对象的成功清掉。主动阅读与数据事实可并存：错误在相关状态位可见、可找回，当前句子和阅读位置保留。面板内需要处理其他问题时，先按B.3结束或安全切换当前任务，不叠层。

#### B.5.2 内容预算与编写契约

常用入口、状态优先一行，正常字号的短反馈最多两行；超过预算先删重复解释，再进入可完整阅读的同层区域，不截掉错误原因、用户输入或关键动作。大字／键盘条件下按LAY-04允许当前内容区滚动，不缩字硬塞。保存与返回在输入面板内可达，并保留简短计时状态；长期数据说明归设置，不常驻首页争抢注意力。

每条动态文字随现有文案资源登记六项：**说的是哪个对象、由什么事实触发、出现在哪、何时退出、被替换后如何处理未完成事项、是否及何时播报。** 这份契约与页面一起审，不另建重复数据库。复用固定键；含义改变须同步适用条件或新增键并保留旧编号。完整句库、轮换和编写方法在[内容资产（附录E）](08-voice.md#copy-authoring)。

锁屏或外部通知只报计时状态，省去小步骤、便签正文及主动情绪类别；未启用或平台不支持通知，仍按真实时间恢复。可访问性验证见[D.25](07-acceptance.md#ui-layout-tests)，连续反馈验证见[D.8](07-acceptance.md#focus-journeys)。

**入口编号按动作识别。** UI01、UI09为退役编号，UI02与UI45分别负责确认开始、回到准备。 UI05打开手动结束确认，UI06才确认结束并按规则记录，UI07关闭确认并回到当时有效的状态。UI08对应启动休息，不用于只切换准备模式。UI12直接创建空标记；UI13只供给某个已有标记补文字。UI12／UI13分别为“留个标记／补充文字”，UI53只退出阅读；新建文字使用UI49，不能把UI13隐式绑定最近一条。UI46—48用于休息控制，UI52—58／UI62用于鼓励类型与退出；UI59仅回准备。UI30表达实际时长，独立的保存状态说明该条是否已落盘；UI33须得到匹配条目的成功回执。关闭鼓励不隐藏这些功能状态。

**记录页命名。** UI100—101属专注页把手。UI63—99与UI24按各行状态执行；UI70／85／86／93已退役，正式分页使用UI97—99。近7天／近30天沿既有统计语义。月份、搜索与读尽状态必须带所属范围，不能让用户误认全库。

**旧标签处理。** “结束这段”“先记一下”“加一句”“写想法”“按现在的需要选”以及鼓励里的“收起”退出现行界面，按上述动作映射替换。保留旧键身份、历史修订与已收藏原文，不能因改名改变行为。正文、读屏、测试和实现同名；“收起想法”仍是另一业务动作，不能随鼓励关闭一起改动。

**变量规范：** `{elapsed}`是唯一进入本版结果模板的变量，必须来自实际已记录的计时，并自带单位，例如“20秒”“10分钟”“1小时5分钟”。小于1秒且大于0可显示“不到1秒”；0使用独立零时长文案。累计先求和再格式化，不把两段20秒显示成0分钟或2分钟。

鼓励句不插入未经处理的任务、便签、姓名、诊断或缺席天数；需要显示小步骤时，使用独立且有长度控制的字段。锁屏通知只用固定通知文本，不把“有点累了”等主动分类或私人内容带出应用。
