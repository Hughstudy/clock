> C.9.10—C.12：输入协调、动作前置、写入清单和逐操作映射。

#### C.9.10 前端交互信息与底表边界

前端临时信息不另建持久业务列；字段含义和同值处理按[字段字典](05-data-fields.md#database-field-contract)执行。

编辑器作用域、输入序号、文件验证序号、当前控件目标和在途操作匹配属于本次协调；已提交草稿使用note_drafts，最小提交去重使用mutation_receipts。不得为UI复制可独立修改的会话、想法或偏好。

普通同值偏好／待看状态不更新业务行与row_revision；原子事务可仅写技术去重回执和commit_seq，回执不计用户指标。参考返回committed_no_change说明本次无业务变化；already_committed只确认原操作且仍读取最新对象。前端未改值可直接不发命令，明确reset则不能被当作无意义补丁过滤。实际命令必须限定字段、来源和期望版本。

来源上下文固定原数据世代；回执或等价受控上下文携带data_epoch、op_id、command_kind、target_id，不用“当前页面对象”猜原目标，也不给旧输入补贴新世代。具体执行见[输入与在途协调](04-data.md#frontend-command-contract)。

#### C.9.11 动作反向索引与字段修改责任

字典中的每个有效字段均须连接到可读动作、可写／移除动作和技术生命周期；退役字段单独列迁移，不作为正常写集合。实现须提供对应清单，初始化、导入／清空与回执单列；有写入方不表示前端可任意编辑。条件写集合表示上界，净变化、时刻与原子边界仍按规则执行。

| 表组 | 正常用户动作写入 | 非用户直接输入的字段/变化 |
| --- | --- | --- |
| sessions | A05—A07/A09/A11—A12/A14；E02核对到期 | ID/开始事实/目标在创建固定；终态冻结，不能给前端统一编辑 |
| notes / note_drafts / note_undo | B01—B09；草稿建立/更新/正式提交/丢弃分别处理 | 首次输入/原归属不可被提交时间改写；撤销源和期限由删除事务生成 |
| quote_favorites | B15收藏/取消 | quote_id和文本来自点击时句库版本；欢迎/资格/故事不混写 |
| app_preferences | 明确时长选择成功开始、C06—C09 | 系统播放/减少动态能力不冒充偏好；last_focus_min非任意可编辑列 |
| story_items / session_stories / world_state / story_rotation | 计时与故事命令的条件写集合 | 节点只存本段检查点；符合RULE-COLLECT的到期才改世界；真实DAY计算器仍须实现，点击／观看不推进 |
| content_grants | 当前无前端直接授予/回收动作 | 只保留已有可证明资格及受控迁移；不借字段启用未来奖励 |
| db_meta / mutation_receipts | 仅受控提交、初始化、替换/清空、维护 | schema升级与世代生成非页面自由参数；回执不含便签原文、不作统计 |

**各表身份分别核对。** note_drafts比较slot＋draft_id，轮换比较scope_kind＋scope_id，故事比较原session_id＋item_id＋内容版本；另核对epoch与row_revision。退役接续不进入运行时条件写入，不能因单例slot相同覆盖另一个寿命的对象。

**增删改取舍。** 不新增编辑器历史、输入序号、失败次数、已读剧情、通知点击和永久重试队列。草稿寿命的防重利用已有稳定ID和必要技术回执；已有receipts_by_target索引可服务该校核。回执清理不能破坏仍可能到来的旧命令防护，容量/清理仍需实际适配评审。不为未启用的外观选用或一次提示虚构配置列。若未来启用，先定义新动作、目标、恢复/删除与备份，再评审新增字段。

#### C.9.12 命令、输入与结果的执行细则

本节定义命令、草稿、故事检查点、输入快照和结果协调的执行约束；它们保持功能语义一致，不指定生产数据库。

<a id="command-execution-detail"></a>

##### C.9.12.1 命令入口、修订与执行结果

业务变更只经受控命令执行，不暴露任意表／字段写入。命令固定原操作ID、数据世代、目标、期望修订及已验证参数；创建身份、草稿身份和原归属在重试时不换。写事务内先查原回执，再核对对象条件；条件写入须恰好影响一行。冲突、0行更新、失效目标不得报成功或生成成功回执；确实无变化的操作需独立且可解释的结果。旧回执仅证明原操作已提交，展示仍读最新对象。

**无变化与回执。** 合法的同值偏好／同状态设定返回无业务变化，不清时长记忆、不推进业务行修订或用户计数；明确重置不是普通同值提交。为安全去重可提交原有最小技术回执并更新commit_seq，不能把该技术变化算成新经历。回执或受控异步调用上下文须关联epoch、op_id、命令与目标ID；只清理匹配的等待，显示仍取最新事实。 同样适用于重复保存相同正文，以及成功开始但last_focus_min原本已等于本次明确时长的情形：会话仍真实创建，未变的偏好不额外增版。

计时暂停／继续／结束携带受控意图时刻和原会话依据，失败重试不把等待时间加进原意图；首次接受时到期仍优先。已提交的竞争终态不能被旧意图覆盖。撤销资格则在实际执行时重新核验，不因旧点击仍保留资格；已成功命令的回执重试不再次执行。详见[执行约束](#execution-detail)。纯内存待存工作不承诺进程退出后无损恢复。

<a id="draft-checkpoint-detail"></a>

##### C.9.12.2 草稿、删除与故事检查点

正式提交想法同时核对draft_id／draft_revision与目标基础修订，只清同一份原草稿；新文字保留首次非空输入时刻和编辑开始时的归属。 edit不产生新的创建事实；其冗余创建字段仅按[C.9.3.5](05-data-fields.md#draft-field-matrix)兼容核对。正式正文确实没变时可清已提交草稿，但不修改notes.row_revision。删除事务清理未经独立修改的原文副本；真实未交修改按冲突草稿保护，不复活已删目标。`has_user_edits`记录有依据的编辑事实，不以非空正文猜测；归属未知的旧想法可由edit草稿原样承接，新稿不能制造未知归属。

故事检查点用checkpoint_effective_ms标明本段有效计时，重返、暂停、结束与导出从同一入场计算。活动故事仅属于同一open实例；结束即关闭，不生成待续。重复采样不重复推进；检查点不写收集世界，只有满足RULE-COLLECT的到期终态才提交world_state。缺计算器不伪造检查点，结构与语义见[不变量](05-data-fields.md#database-invariants)。

<a id="frontend-execution-detail"></a>

##### C.9.12.3 前端意图、输入快照与在途协调

**来源绑定。** 创建、修改、重试及异步回调携带来源界面／编辑器绑定的数据世代、对象、版本和本次作用域；不能临时读取新世代给旧输入重新贴标。切换对象、明确放弃、替换或清空后，旧作用域不再产生新命令；已受理命令的真实结果仍按原ID核对，不能用关闭面板推断回滚。

**输入屏障。** 编辑输入序号与数据库row_revision分别管理。正式保存捕获可见输入快照，先等待该快照对应草稿写入确认，再以该draft_id／draft_revision和原目标提交；未完成输入法组合不正式提交。迟到自动保存只确认它对应的输入序号，不清更晚输入。正式保存后出现的新字仍保护，承接为针对该正式条目的新编辑草稿时核对最新目标和单槽位；竞争则保留本次缓冲并明确处理。create/update/discard自动保存调度未在当前参考完整实现。

**草稿寿命。** 自动保存按本作用域顺序协调、条件更新同一草稿；提交、放弃、被替换后的草稿不得由迟到upsert复活。旧草稿保存回执不能清后来新稿。归属在编辑开始冻结，首次非空输入时间不改成自动保存／提交时间；正文选中、粘贴、输入法提交和撤销编辑按同一输入依据维护，不新增逐键持久记录。

**在途次序。** 本版同一会话变更结果未明确前，同动作复用原意图，依赖其结果的反向控制不可按旧版本并发提交；局部保护不锁死页面阅读和导航。暂停／结束的本页受理状态按原受控时点停止并标待存，不冒充已写入，也不因失败等待加时。未受理的同字段偏好可合并为最新明确值；已发出操作结果先核对，不换参数复用op_id。仅无关字段修订变化且待改字段基础值未变时，可按新版本构造新命令；同字段竞争不自动覆盖。

**三类取消。** 未受理操作可取消且不写事实；已受理／提交中只停止后续展示并核对原结果，不能据取消假称未发生；已提交的改变只能经已有明确反向动作处理，不因离开自动补一个撤销命令。程序性恢复焦点／控件重建、重复事件与过期提示不生成新用户意图。

##### C.9.12.4 动作、字段与状态的完整对应

**按意图枚举，不按按钮数量枚举。** 当前52个ACT主编号拆成105项分支：读/临时、持久草稿、业务变更、条件维护和未启用能力分别标明。每项必须有来源状态、读取字段、允许写入字段、条件事务、成功/无变化、已证实失败/提交未知、取消与返回去向；无持久写入也须显式写明。完整索引见[对应规格](#action-field-matrix)，字段逆向检查见[C.9.11](#field-reverse-index)。该覆盖针对本版定义范围，不宣称穷尽任意设备行为或未来能力。

**失败不是一种状态。** 已证实拒绝、版本冲突或事务回滚时，可释放严格匹配的在途操作，保护输入、重读后由有效新意图继续；超时、关闭面板、未收到回执不证明未提交，须保留原身份核对。旧失败不能释放新请求，失败重做不能沿用失效对象版本。纯读取失败也不得借“重试”重放业务变更。

**同一行合法，不代表这次修改合法。** 受控命令同时校验变更前后：冻结身份/创建事实不变、净变化才+1、终态不重写。参考事务执行行校验和前后校验，并在回执及commit_seq写入后再核对；超过安全整数边界时整笔拒绝，不能提交后才发现控制值无效。生产适配按实际影响对象校验，不要求每个按键全库扫描。

**草稿、收藏及核对到期各有命令。** 草稿create/update/discard不得被无条件upsert替代；对当前有效收藏的重复操作不改原快照。系统核对当前会话不是用户手动结束：未到期保持运行、已暂停保持暂停、已结束不重算，到期按原截止点结算；真实故事仍经内容计算器，不借普通计时路径绕过。

**确认恢复与确认回执分开。** 第一次执行替换必须重核活动会话、输入与数据库版本；同一计划已进入其新世代后，再次核对只确认已完成，不因新输入而覆盖、丢弃或重复替换。新输入保护仍有效，但不是把已完成操作重新执行的前置要求。

底层含义与当前策略由功能与数据规格维护；作用域、输入序号、在途失败状态、预览计划及查询游标属于本次协调，不新增用户行为日志或永久重试队列。未定外观选用、历史纠正、回放、奖励提示状态不因出现在枚举里而启用或虚构字段。

### C.10 动作前置与组合约束

#### C.10.1 对所有动作采用同一推导方式

动作首先回答目的和对象，其次区分只读/临时输入/持久草稿/正式事实/技术维护，最后检查时序。准备值不生成会话，草稿已保存不等于正式想法，回看不重执行故事，隐藏不取消资格。读界面可以共享组件，写入必须分别路由到自己的受控命令。

失败路径也要闭合：未受理可取消；已受理结果不明保留原意图；确认未提交后释放与它匹配的在途，重读或重新编辑；确认已提交只更新原对象回执，不能关闭后来打开的编辑器。结果信封不要求页面显示技术字段，但必须能定位到正确作用域。

字段匹配不是“每个按钮至少写一列”。某些动作正确对应零业务写入，维护动作没有按钮也可能写库。共同元数据与回执由事务层维护，不能让前端通过payload自由设置。设置同值、收藏同值和空记号原样保存不改变相应正式对象内容；清理已提交草稿本身仍是事务中的实际变化，不能把“正式正文未变”误报为整笔完全无变化。

#### C.10.2 草稿与收藏的完整寿命

**草稿。** 打开新输入器可只保留本次上下文；首次实际输入需要可靠保留时才创建新草稿。创建须确认单槽位、预分配条目身份和未使用的draft寿命；update带原ID/版本，不作为upsert；submit核对可见快照、草稿和目标版本；discard只删除明确那一份。重复原命令读回执，新命令却使用已退役draft_id必须拒绝。可利用已有技术回执和稳定ID，不新增永久草稿坟场或逐键日志；回执回收策略不得破坏仍需的防重。

同一槽位不等于同一草稿。补字沿原note；另存是明确的新对象，需要重新说明归属与创建依据，不复活旧目标。新身份的创建时刻采用该明确另存所捕获的新建输入依据，不复制旧note的历史创建事实；具体冲突对比/另存交互仍待实际实现，本版不伪称已提供自动合并。

**收藏。** quote_id有稳定关系身份；有效收藏保持原版本、文本和时刻。重复点收藏不自动升级句子。取消清正文但保留必要关系版本；取消后明确再收藏，写本次可核验文本与时间。取消与再次收藏的并发由版本/回执协调，而不是删除行后丢失身份。欢迎、资格、外观、章页不强塞进quote_favorites。

**计时核对。** 生命周期事件核对已有会话，不等于用户按了结束。运行且未到期保持原状；暂停保持原余量；到期才归档；已结束仅确认现状。实际调用可在读阶段发现需要结算后才发命令，不能按每秒tick持续写无变化回执。真实故事参与的暂停/结束/导出仍必须接内容计算器。

#### C.10.3 状态守卫与组合覆盖

| 轴 | 必须区分的等价类 | 处理重点 |
| --- | --- | --- |
| 会话 | 准备、focus运行/暂停、休息运行/暂停、已结束 | 开始只在无活动；暂停/继续分模式；系统核对不偷换为manual |
| 输入 | 无稿、新稿、编辑稿、原目标改变/删除、已退役稿、组合输入中 | 唯一槽位/身份/基础版本，不能把输入状态当正式条目状态 |
| 数据能力 | 正常可写、只读、仅内存、未保存、未知提交、配额不足/损坏 | 可读内容保留；不报假保存、假空库；局部动作与整库能力分开 |
| 生命周期 | 同页、切页、后台、关闭/重开、跨日/时区、多窗口 | 冻结来源、核对原截止、保留锚点；进程退出不保证最后写入会完成 |
| 命令 | 未受理、在途、已提交、已证实未提交、结果未知 | 身份匹配的释放/重试/取消；不混用新意图和原操作重试 |

每项操作须列出合法前置状态和禁止组合。以普通路径、边界值、失败重试、两操作竞争、破坏性操作和长期读取各取有意义的组合；不以机械排列数量代替有效场景覆盖。D.24含跨模块长链测试，实际前端还要验证输入法、指针取消、读屏、焦点和真实异步调度。
