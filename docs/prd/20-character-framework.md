# 人物创作框架与原则

> [返回文档地图](README.md) · [交互形式与场景提案](19-character-in-app.md) · [已确认性格](10-character.md) · [完整章稿交接](12-stories.md)
> 2026-11-21，工作稿。承接用户“完成刚刚的人物，再具体化设定框架和原则，并再次复盘”的要求。本稿提出创作方法与取舍，不把新偏好、演法或台词自动定为正式设定，不启动应用制作。

<a id="character-framework"></a>

## 1. 人物先用一段话说清

**它喜欢把普通的小事弄出一点自己的意思。会认真试，也会为自己的小成果高兴；到了合心意的时候，就能停下来享受。它与你亲近，愿意回应、分享，偶尔主动为你留一份，同时也有自己正想做的事。**

这里的辨识度来自两个同时存在的倾向：对自己的小趣味有主见，对与你相处这件事很大方。它可以喜欢一个普通甚至有点不齐整的结果，不必每次聪明、每次出错、每次送礼。

“小得意”是上述选择的表情和口吻，不另列一种主性格。“笨拙”是偶尔出现的局限，不负责让每集故事启动。已有三项确认性格继续有效；本稿是在有限 App 表达里安排其主次，不扩充一份性格词汇表。

## 2. 设定分四层，避免越写越重

| 层次 | 要确定的内容 | 本轮建议 | 不需要补的内容 |
| --- | --- | --- | --- |
| 稳定动机 | 为什么愿意做这些小事 | 想试试、想弄成自己喜欢的样子，也能享受现成的小乐趣 | 伟大目标、必须完成的人生任务、等待用户解决的缺憾 |
| 选择习惯 | 同一个普通活动，它会怎样做 | 偶尔加一点自己的意思；愿意调整；合意了便能停 | 所有活动一律创新、每次先失败、固定招牌动作循环 |
| 相处方式 | 如何把善意给到用户 | 对主动触碰明确回应；有合适的机会便分享；不要求答复 | 读心、索取安慰、以使用次数换亲近、无理由的冷淡 |
| 当次表现 | 今天画面里具体发生什么 | 一个具体愿望、一处可见选择或关系动作、一个能停驻的落点 | 新身世、多个性格标签、一整段解释人物的旁白 |

前三层帮助不同作者写同一个角色；第四层负责实际体验。某一设定如果只能在前三层解释，始终找不到第四层证据，先退出制作范围。也不需要每张卡表现全部四层：日常活动允许只是舒服地存在。

## 3. 它的“有主见”具体落在哪里

先采用三条可反复使用的选择习惯，每条都允许不出现。它们是写作方向，不是随机概率、行为树或运行时人格值。

| 选择习惯 | 可读的表达 | 过头的写法 |
| --- | --- | --- |
| 够用了，也可以加一点喜欢的东西 | 积木不高，小旗仍是它在意的部分 | 每次必须发明新用途，反复装饰直到完美 |
| 自己喜欢，就能满足一会儿 | 看一眼自己的小作品，随后安静待着；无需用户夸奖 | 一直展示、摆姿势、问“是不是很棒” |
| 自己有一份，愿意也给你一份 | 两杯已经存在的茶，一杯自己喝，一杯明确留给你 | 把所有兴趣改成服务用户；假称做了未表现的劳动 |

这不是三个段子的无限复用。一个人物可以在积木里坚持小旗，在阅读里只顾投入，在喝茶时想到分享；共同之处是选择有来由。若拿掉角色名字，换成任何一个勤快、礼貌的服务员也完全成立，就需要补回它自己的愿望，而不是追加俏皮话。

**允许普通时刻。** 专心、发呆般看云、安心喝水，都可以成为内容。鲜明来自少数可信的选择反复被认识，不要求每次出现都表演“我很有个性”。

## 4. 亲近与照顾要有对象，也要有分寸

用户希望的是有爱人般的亲近感。第一轮用“它对我有明确回应，也会主动把我考虑进去”承接，不急着靠昵称、甜话或频繁表白解释关系。

| 相处情境 | 建议表现 | 不引入的含义 |
| --- | --- | --- |
| 用户真的点了它 | 在可交互状态给出一段明确、温和的回应，再回原来的事 | 不用故意不理人证明独立；回应次数不计关系进度 |
| 它在享受自己的生活 | 偶尔给用户留一份，必要时用“这杯给你。”说明对象 | 不等领取、不反复询问、不把没有点击写成拒绝 |
| 用户请求鼓励 | 回应这个明确请求，说当下能成立的话 | 不通过想法文本推断隐情，不诊断情绪，不许诺解决现实困难 |
| 用户正在输入或处理问题 | 让操作、可读信息和真实状态优先 | 不给每次收起控件配“我懂你”的情话；工具体贴不能全算人物魅力 |
| 用户暂停、提前结束或很久没来 | 保持原有善意，按真实状态停驻或恢复 | 不失落、不追问去向、不拿缺席制造情节，也不假称一直等待 |

**不讨好，不等于需要拒绝用户。** 它的自主主要来自它有自己的事、偏好和满足；工具操作仍应可靠，亲近也不必忽冷忽热。

**照顾，不等于每次劝休息。** 它可以关心，但不做效率教练、健康监督员或全知安慰者。用户没有给出情绪输入时，分享一杯茶比声称“知道你今天很累”更可信。

**爱人般的感觉也不等于索取。** 可以直接、温暖、偶尔主动；不引入排他、嫉妒、忠诚测试或“我都为你做了”的关系负担。是否喜欢这份亲近，仍由实际样稿验证。

## 5. 情绪可以有起伏，不必永远微笑

保留有兴致、专心、自得、短暂不满意和亲近几种简单状态。区别主要来自当下行动及结果，表情只辅助，不能让细小眉眼独自承担故事。

它可以对摆法不满意、愿意重新试一处，也可以发现现成的样子就很好。小不满须有画面里的具体原因，并能由它自己处理或放下；不归因于用户暂停、结束、关掉动画或离开。

不为“有情绪”新增一套情绪值，也不要求每段经历起伏。没有失误和反转的一段安静阅读，完全可以成立。若一句台词需要连续三种表情、几次转身才能解释，就重写这句或缩小这件事。

## 6. 写一张小场景卡的方法

先填下面七项。它是进入[完整章稿模板](12-stories.md#chapter-brief)之前的创作筛选，不复制时长、节点和保存规格；通过后才按正式模板补齐。

| 必填项 | 必须具体到什么程度 |
| --- | --- |
| 真实入口 | 现有哪项活动、哪次用户操作或哪种合法状态；新增入口须明确标出 |
| 它自己的愿望 | “想搭个喜欢的小作品”可以；“展现好奇与温暖”不是愿望 |
| 这张的重点 | 自己的趣味、主动分享、对触碰回应等选一个重点；可以只是普通生活片段 |
| 可见证据 | 用户能看到哪处摆放、姿态、结果或读到哪句意愿；不能只写内心想法 |
| 最少表达 | 先用已有物件、一个主要状态变化、至多一句可选文字；若超出，说明不可替代的价值 |
| 停止与重看 | 用户不点、错过过程、提前结束、重复出现时，是否仍成立；不许补造完成事实 |
| 新增制作 | 图稿、道具状态、动作接触、文字触发、输入目标和记录内容分别有哪些；复用不等于免费 |

“一个主要状态变化”是首轮概念稿的收敛目标，不是允许省略必要中间状态。涉及手物接触和会话进度时，正式实现仍要完整、连续、可中断。

**三个首选样稿的分工：** 积木卡检验自己的趣味；两杯茶检验主动想到用户；读书时回应触碰检验自主与亲近能否同时成立。具体卡见[APP-S01—S03](19-character-in-app.md)。它们分别承担一个重点，不强塞成一个重复的剧情公式。纸船物件点击仍为后续候选，不是首批必需功能。

**不以文字制造画面债。** 先写“画面里确实有什么”，再写一句画面不容易表达的意愿。例如积木和旗确实在眼前，才可以试“就这么高。旗子得有。”；有两杯且分给用户的安排已成立，才可以试“这杯给你。”。这两句是待评稿的例子，不是新增自动播放台词。

## 7. 写小故事、关系片段和普通生活，分别算清楚

| 内容类型 | 成立的条件 | 需要避免的混淆 |
| --- | --- | --- |
| 独立小故事 | 有具体愿望、一次选择或变化，以及相应落点；不必包含失败或反转 | 不因只有两张概念图就声称完整章稿交付；不把普通触碰算故事完成 |
| 关系片段 | 一次真实互动或主动分享让用户感到它有回应 | 不要求编造冲突、成果、奖励或永久物件来证明有价值 |
| 普通生活 | 它舒适地做自己的事，画面能安静停留 | 不硬加笑话、失误和对白；也不宣称每段普通活动都已充分表达性格 |

一批内容需要有节奏，但不先规定“几成独处、几成照顾”。先排在一起看：是否全是送礼、全是失败、全是邀功，或全是没有选择的机械活动；发现失衡再改稿。当前场景轮换机制不因这份编辑检查自动改变。

人物弧光先采用**具体小事有变化，基本相处方式保持稳定**。读者可以越来越熟悉它，但不把“用户认识了它”误写成“角色解锁了更高等级的爱”。前一次的事实只有在真实保存、能可靠还原时，才能成为后一次的前情；背景传记不冒充共同经历。

## 8. 给表达分配成本

先尝试静态关系，再尝试一个必要动作，最后才考虑增加用户操作。台词如果是表达关系所必需，可以使用，不设“绝对无字”标准。

- **优先：** 现有道具和姿态能承接的选择；落点可停驻，短暂附加趣味可以错过。
- **慎加：** 一只新杯子、一种新摆法、一句新内容的合适宿主。分别记制作与状态成本，不能称为零成本换皮。
- **后置：** 场景物件点击。先证明没有新输入时角色仍有吸引力，再处理命中区、键盘、减少动态、重复点击与取消。
- **当前放弃：** 精细手指表演、长距离取物、多场景追逐、多人物对白、自由聊天、用户帮助通关和连续照顾任务。

操作时的优先顺序是：可靠的工具与状态信息 → 用户明确请求的回应 → 可有可无的日常表现。这里是创作让位原则，不取代现有反馈协调代码。不要为了让角色演完，挪按钮、延迟退出、丢草稿或延后失败提示。

## 9. 再复盘四轮，具体改了什么

以下是文稿反例检查；没有新增网络研究或用户试验。保留取舍结果，实际吸引力仍未验证。

| 复盘角度 | 发现的问题 | 这轮修改 |
| --- | --- | --- |
| 人物是否过于理想化 | “好奇、认真、温柔”容易变成事事正确的角色；“小得意”若独列又容易每集邀功 | 把重点放回具体偏好和自己能满足；允许普通结果、小不满与无表情的专心，不新增缺陷清单 |
| 简单画面是否真能表达 | 小城堡的趣味可能全靠用户认出建筑，实际又增加改图与解释 | S01 改用已有低矮积木与旗；先看自己的取舍能否读出来，不能仅凭文案判成功 |
| 亲近是否退化为服务或冷淡 | 每次送东西会失去自己的生活；一味强调独立又容易显得疏远 | 把主动分享与明确回应分别做样稿，同时保留只投入自己兴趣的生活片段；不规定伪精确频率 |
| 长期使用是否逼迫追看 | 每段都必须成长、出错、送礼会很快套路化，也要求记住前情 | 区分故事、关系片段、普通生活；主要意义能停驻，核心善意不随完成率和互动数变化 |

复盘后的删减：不再把兴趣数量当性格；不把小得意和笨拙各扩成一条人物弧光；不为建筑名称新增一套美术；不把长期陪伴写成升级感情；不把每个计时操作都附会成关系表达。

## 10. 怎么判断下一张稿值得继续

先看真实入口、表达成本和事实边界是否成立，再看是否有趣。规则合格只说明值得试看，不能证明会让人喜欢。

审稿时做五种看法：只看结果图；看静态替代；去掉可选台词；完全不点角色；重复看几次。每张回答它承担的那个问题即可：我能否看出它自己的选择，或明确感到它在回应我？若完全看不出来，改图或缩小主张；不靠补传记解释。

再检查中途结束、页面隐藏、回来看旧记录、保存失败、输入或阅读被占用的情境。创作不得制造未完成的成果、未保存的记忆或必须补完的待办。手动小记、自然到期整页及未来故事收集资格仍遵守[现有规则](02-features.md#rule-collect)。

最后由用户评看首批小稿，再做少量目标使用者的定性试看。应问“你觉得它正在做什么、像什么样的伙伴、哪里有意思或有负担”，避免只问“是不是很可爱”。没认出设定词不是失败；需要作者解释一长段才觉得有趣，才是要回去改的信号。

本轮交付止于文档：交互清单、性格取舍、场景提案与创作框架。没有新图稿、运行原型、应用改动或用户验证。下一步优先验证少量场景，而不是继续扩写一份更长的身世。
