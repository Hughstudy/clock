## 1. 先看总体安排

**先判断此刻适不适合开口，再确定交流目的，最后在合适的话里变化。** 用户需要容易开始、容易离开，也能在主动靠近时得到清楚的回应。人物有自己的趣味，对用户亲近；语言不监督、不替用户解释心理，也不需要每次操作都予以评价。

| 语言层次 | 负责什么 | 是否随机 | 与人物关系的联系 |
| --- | --- | --- | --- |
| 工具文字 | 按钮、时间、对象、保存结果、异常与下一步 | 固定，由真实状态决定 | 可靠与可预测；无需借角色之口说所有事实 |
| 简短回应 | 开始、收尾等少数转换时刻的一句话 | 适用池内变化，也允许省略 | 接住动作，不把每次操作解释成自我成长 |
| 主动支持 | 用户明确要鼓励、选了当前需要 | 同一交流目的下变化 | 先回应用户，再适度带入自己的口吻和生活 |
| 人物闲话 | 偏好、发现、小主意、自得与分享 | 只在有合法宿主的情境内变化 | 让用户认识它，也感到它愿意把自己的生活分享出来 |
| 故事与回忆文字 | 当前故事的意愿、结果及真实历史 | 当下可选；历史采用原快照，不重抽 | 熟悉来自真实经历，不是亲密等级或后台编造的往事 |

**当前实现。** 随机功能已完成；随后从 `b132621d8dc090600270a94f25531d972b6b0fd9` 对177句逐句精修，当前61句：22句自动节点话、39句主动支持，旧工具节点池已撤出资源。每次打开重新随机起句，每次合法触发直接抽取，只避开各池上句；不采用整组轮完机制。工具节点降噪、共享间隔和退让已接入。删改依据见[逐句审稿](24-copy-review.md)，验证见[精修报告](../verification/companion-copy-review.md)。原有48句日常候选、物件闲话与完整故事继续待实现。

**阅读约定。** 下文 LS01—LS44 是文档场景编号，不是新事件或数据库字段。“固定”沿用功能文案；“候选”是本次试写，不直接替换已发布文字；“不说”是明确的设计选择。新稿不要求增画面、动作或按钮，除非对应行注明待实现及成本。

## 2. 展示与退出方式

各场景采用下列方式，空间与无障碍细则仍由[页面文字契约](03-ui.md#feedback-lifecycle)维护。共用降噪与随机规则只在[E.2](08-voice.md#language-selection)维护，不另做一套计时器。

| 方式 | 出现与停留 | 退出与抢占 |
| --- | --- | --- |
| 功能位 | 对象附近的标签、状态或结果；重要事实完整可读 | 随该对象真实状态更新；未解决错误不能自动装成正常 |
| 转换短句 | 既有伙伴气泡，正常字号一到两行，不新增阅读步骤 | 下一相关动作、面板或切页即让位；开始后的气泡随专注界面退让一起退出；不排队、不补播 |
| 主动阅读 | 既有鼓励阅读区；短句或一到两句完整支持，可换句、收藏或关闭 | 不自行超时换句；临时输入或确认结束后可回到原句；明确关闭则结束，不追问效果 |
| 页面正文 | 空态、记录页、欢迎笺或说明中的静态文字 | 用户翻页或离开即可；滚动、筛选不重新抽句，不逐段播报 |
| 未来内容阅读 | 已明确设计的物件或故事阅读区域，按该功能原有进入／返回规则 | 只在宿主实现后使用；不把普通装饰变为隐藏按钮，不复用鼓励入口冒充日常闲聊 |

准备态与结果态的转换短句可以留到下一相关动作；它不构成必须处理的消息。自动内容不做倒计时、稀有提示或未读提醒；错过不会损失结果或关系，未来仍可在适用场景自然出现。主动阅读和工具状态分区处理，不能用一句闲话盖住保存问题。

## 3. 进入、专注与休息：LS01—LS16

| 场景与用户处境 | 语言设计、目的与样稿 | 出现、变化和退出；现状说明 |
| --- | --- | --- |
| **LS01 首次打开**：想知道怎么开始 | 默认让计时入口清楚，不强制欢迎话。可主动读欢迎笺；正文负责介绍相处方式，不要求先选心情 | 页面正文；首屏不随机欢迎、不弹领取。当前新装首屏安静，欢迎笺可读；当前笺文见08，本轮已精修 |
| **LS02 再次打开且没有活动会话**：可能只想看一眼 | 已有使用记录、没有活动会话和待展示的专注到期结果时，可以招呼一句。例如“来啦。先不急着开工。”；不统计离开几天、不追问去向 | 已接入RET 5句，每次打开且启动恢复成功后随机选；页面须可见、保存正常、节点话开启。首次使用、切页和回前台不抽招呼。点开始让位，恢复原段走 LS03 |
| **LS03 恢复运行或暂停的原段**：需要先知道发生了什么 | 固定说明真实运行／暂停状态、可继续或结束。无需欢迎和重新鼓励开始 | 功能位；刷新、同步和回前台不抽新句，不重演第一次开始；已有恢复机制 |
| **LS04 改时长、准备模式或本次意图**：正在设置 | 数字、范围、应用／取消说明准确；角色不评论长短、不评价写下的目标 | 功能位；调整不抽句，不因设置120分钟更热情。已有入口；固定名称不改 |
| **LS05 明确开始专注**：准备把注意力转走 | 可一句“开始了，我陪你做这一小段。”；若沿用既有句，也不追加第二句。表达陪伴，不宣布任务完成或人格进步 | 转换短句；会话建立及必要保存事实成立后，按共用降噪筛选。退让后安静，不因未读持续展示；STA 5句、共享降噪及退出联动已接入 |
| **LS06 正在专注、没有新操作**：通常看着 App 之外 | 不自动搭话。人物自己的活动继续，时间与必要状态可见 | 不因过半、剩余一分钟、鼠标停留、设备昼夜或长时间不点而换句；已有无 tick 选句机制保留 |
| **LS07 暂停／继续专注**：原因未知，希望迅速完成操作 | 默认只显示“已暂停”或“计时中”等固定状态。不给暂停附会疲惫，也不为继续追加表扬 | 功能位；本轮减少自动节点话，原 PAU／RES 池已撤出运行资源，原文在24留存；固定状态继续保留 |
| **LS08 打开结束确认／取消确认**：正在作决定 | “结束本次专注？”及真实后果；取消则回原状态。角色不说“再陪我一下”，也不提前道别 | 功能位；确认期间无闲话；取消不换鼓励、不发结果。已有确认与阅读保留机制 |
| **LS09 手动结束，实际时长大于0**：想收尾 | 真实时长与保存状态固定显示。可选“好，这段就到这里。”或“辛苦啦，先松口气。”；不说“没完成也没关系” | 转换短句；保存失败只讲问题，成功后才适用相应结果。共享降噪可省去可选句，固定收尾仍完整；未来短章只记实际落点 |
| **LS10 开始后立即结束，实际时长为0**：不需要被劝回 | 固定记录0秒及保存状态。若适合说一句，用“好，先停在这里。”；不声称投入过一段时间 | 与 LS09 同等语气，不缩水、不补偿式夸奖。快速开始后受共享降噪，通常无需第二个气泡；不改变0秒事实规则 |
| **LS11 自然到期**：这一段结束，现实任务状态未知 | 时间、结束和保存事实清楚。可与 LS09 共用“辛苦啦，先松口气。”；不说“任务完成”“比上次更棒” | 转换短句；结束原因由功能与记录说明，不靠强弱表扬区别。若未来完整故事且保存成功，可呈现其合法结果，但仍最多一条可选话 |
| **LS12 后台到期，稍后回来**：需要看现在的结果 | 固定呈现已经结算的时间与保存状态。不补“刚刚完成了”，不补播伙伴错过的台词 | 功能位；不补排开始、完成、休息等历史气泡。回看真实记录可选，后台不产生新的角色生活事实 |
| **LS13 选择短休、长休或返回专注准备**：还在安排时间 | 只说明选中时长与接下来按钮会做什么；选休息不等于已经休息 | 功能位；不提前讲“歇好了”，不鼓掌，不生成新话语事件 |
| **LS14 明确开始休息**：可能马上离开手机 | 可一句“歇会儿吧。”，也可以安静。若刚结束专注已说过，通常只显示休息计时 | 转换短句；共享降噪，不把休息作为聊天邀请。BRK 6句与新随机、降噪规则已接入 |
| **LS15 休息中、暂停／继续／结束休息**：由用户决定怎么休息 | 过程不搭话；暂停、继续用固定状态；结束说明休息计时结束及可选操作，不断言已经恢复精神 | 功能位为主；原 BRE 池已撤出运行资源。无“该干活了”、不自动开始下一段；主动求支持仍可用 |
| **LS16 准备下一段**：只是准备，不等于启动 | 读数与“开始专注”明确即可。角色保持自然姿态，不鼓励连续打卡 | 功能位；准备不抽新句。真正开始再判断 LS05，不以第几段增加亲近等级 |

## 4. 记录想法：LS17—LS20

| 场景与用户处境 | 语言设计、目的与样稿 | 出现、变化和退出；现状说明 |
| --- | --- | --- |
| **LS17 留个标记**：想快速腾出注意力 | 固定“已记下一个标记。”，与空文字事实相符。不追加“又分心也没关系” | 功能位；保留实际撤销机会。原 NME 轮换不再作为默认自动话；不改变标记和撤销规则 |
| **LS18 打开编辑器、打字、切草稿、恢复草稿**：在组织想法 | 标签、归属、草稿选择和冲突说明清楚；角色不提问、不分析输入、不按字数回应 | 功能位；输入优先，草稿自动保存不触发新鼓励。只在确有草稿时说可恢复 |
| **LS19 明确保存文字并返回**：希望放好再继续 | 固定“想法已保存。”，失败则准确说明。保存、返回只完成一次确认，不补“你终于记下了” | 功能位；原 NTX／BCK 内容不再默认叠加。暂时盖住主动阅读后，可回原句；没有原阅读则安静回计时 |
| **LS20 编辑、删除、撤销或遇到版本冲突**：需要确定改变了什么 | 只说实际对象及结果，例如已删除、撤销成功；有冲突时说明最新版本与可选动作 | 功能位；不以“舍不得”“还是留着吧”替代确认，不从内容评价用户。支持哪些动作由真实实现决定 |

## 5. 主动请求与收藏：LS21—LS26

主动入口继续叫“给我一句鼓励”，四类名称不变。因此每类首先提供相应支持，不能把纯粹的物件笑话随机塞进来。丰富度来自直接关心、具体建议、适度分享等不同方式；不规定每句以“我”起头，也不要求每句先肯定人格再作总结。

| 场景与用户处境 | 语言设计、目的与候选说法 | 出现、变化和退出；现状说明 |
| --- | --- | --- |
| **LS21 日常鼓励**：想得到一点支持，没有说明具体心情 | 可以直接陪伴：“不用一下子做很多，我陪你做一点。”；也可以分享自己的取舍：“我搭积木也会先试一个摆法。不好用，再换。” 不假定焦虑、疲惫或失败 | 主动阅读；本次默认 ASKG。适用内容内随机变化；先提供可直接理解的支持，不强制阅读角色寓言。新说法待评稿 |
| **LS22 开始有点难**：主动选了这个类别 | 给一个可采用、也可不采用的小起点。“先找一件不用准备就能动手的事，做那一点就好。”／“不用先想好全部，先挑一个顺手的地方。” 不布置新任务列表 | 主动阅读；不由准备态停留时长触发；后续句可以是陪伴或小办法，不连续十句教同一招 |
| **LS23 刚被打断**：想重新接上 | 先承认接回来的过程。“先看看刚才做到哪儿，不用马上接得很顺。”／“接得上就接；想换个起点，也行。” 不判断谁造成打断 | 主动阅读；只因本次类别选择适用。不因切页、暂停或留标记自动进入，不把已结束旧段说成可继续 |
| **LS24 有点累了**：主动表达了疲惫 | 更直接一些：“嗯，那就先歇会儿。现在不用急着决定下一件事。”／“这一会儿，什么也不安排也行。” 不先绕一段自己的故事，不要求证明已经休息 | 主动阅读；允许短而温暖，不强加笑点、效率建议或“休息完再努力”。不承诺替用户处理现实任务 |
| **LS25 换一句、换类、关闭、临时转去写字**：用户管理阅读 | 换一句留在当前类别；换类立即给相应内容；关闭直接结束。临时编辑／取消确认后保留原句，无需“还想听吗” | 主动阅读；明确请求不受自动短句降噪限制；无额度、无连点奖励、无随机播放。入口与直接随机选句已实现 |
| **LS26 收藏、取消或收藏失败**：保存的是这一句 | 只显示收藏的真实状态，成功才“已收藏”；取消不失落，不说“原来你喜欢这样的我” | 功能位与原阅读并存；收藏绑定点击时版本，换句不改变待处理对象。不将收藏分析成情绪或亲密偏好；已有快照机制保留 |

这些候选用于检验口吻与适配性，不是整库定稿；不在本轮覆盖原 ID。当前39句主动支持的文本与版本在[句库](09-encouragement.md)逐句对齐，后续修改须同时维护资源版本、适用条件和收藏兼容。

## 6. 触碰与人物生活：LS27—LS33

亲近先由可靠的回应成立；不靠“每碰一下必说新话”鼓励反复点击。默认沿用已有动作反馈。下面触碰文字属于后续原型候选，未与现有手势接通，不等于新增聊天入口。

| 场景与用户处境 | 语言设计、目的与候选说法 | 出现、变化和退出；现状说明 |
| --- | --- | --- |
| **LS27 摸摸**：一次亲近的接触 | 动作回应为主。若试文字，可用“嗯，挺舒服的。”一类短回应；有阅读场景依据时可试“嗯。我还想把这页看完。”，回应后回自己的事 | 新文字须先有明确触碰语义与触发设计；正常专注默认只动作。准备／暂停／结果／休息中的可选短句同样受共用降噪，不为说话暂停计时 |
| **LS28 击掌**：想得到一个简单的互动 | 动作已足够清楚。可选“啪。”或“接住了。”，仅在击掌回应实际成立时；不写成完成任务的庆祝 | 当前有击掌动作；文字待试。不是任意点身体都说击掌，也不提高互动分数；减少动态时保留可理解回应 |
| **LS29 轻压回弹**：玩一下软软的角色 | 默认无字。若后续试稿确有可读的按压与恢复，可试“好啦，又圆回来了。”，不需要再演一段害羞或生气 | 只能对应实际反馈；禁止写疼痛、委屈或逼用户道歉。静态状态不支持“又圆回来了”时不用此句，保留无字回应 |
| **LS30 快速重复触碰或与工具操作交错**：可能只是随手点 | 动作有限回应，文字不排队、不每点换句。不说“还要”“再来一下”制造点击任务 | 新输入按既有取消规则处理；工具、错误、输入与主动阅读优先。每次是否有文字可不同，基本善意和动作可理解性保持稳定 |
| **LS31 活动进行中，或看到某个小结果**：可能只瞥一眼 | 运行中不为新节点自动弹台词。若以后有主动查看或合适的收尾宿主，可说偏好、想象和选择；例如积木与旗已在眼前时，“就这么高。旗子得有。” | 活动通道已有，日常文字宿主与完整故事未实现。语言表达看不出的意愿，不编眼前没发生的动作；无入口时稿件留在候选，不偷偷塞进鼓励 |
| **LS32 故事收尾、主动分享**：看见实际落点 | 未来两杯茶均存在且分给用户的安排成立，可用“这杯给你。”；未完成只呈现真实进度，不补送成品、不叹气 | 接完整章稿与收尾，不增加气泡数量；自然到期、故事完整且保存成功才收集。手动短章可回看，文字不能改变资格；二杯茶尚未制作 |
| **LS33 主动查看已设计的互动物件**：愿意认识它的生活 | 小话以偏好、发现、趣味为主。“还是窗边好，发呆也有个方向。”／“这杯子没什么讲究，我用得有点讲究。” 条件须符合现成物件 | 未来内容阅读；普通装饰与当前小屋图片索引不触发。每次进入保持同一句，明确重新查看可变化，不靠反复点开解锁稀有句；历史事实按保存来源，不能重抽成另一次经历 |

**语言能补充内心，不能伪造动作。** “我喜欢窗边”是偏好，不要求专门动画；“我刚替你把窗关上了”需要已发生的关窗事实。角色可以猜测、想象或表达自己喜欢什么，但不虚构读过用户的便签、知道用户没说的情绪，或曾与用户一起经历未保存的故事。

**不提出接不住的问题。** 没有回答入口时，不说“今天发生什么了，讲给我听吧”；普通闲话也不要求用户用按钮选答案。语言中的小趣味不自动新增对话树、摄像头、语音或自由输入。

### 十一项现有活动，各自适合聊什么

这是 LS31 的内容分工，**不是十一种新增自动触发**。活动已有，下面闲话尚未接入；只有以后确定了主动查看或符合规则的收尾宿主，才从对应活动选句。每一类先建立可变化的谈话方向，不为了填满句库给所有活动编同一种笑话。

| 活动 | 适合的语言方向与候选 | 条件与变化边界 |
| --- | --- | --- |
| F1 准备一餐 | 自己喜欢的味道、对尝味道的期待；“尝味道这一步，我很认真。” | 有实际试味才用作当下反应；否则只能写一般偏好。不声称给用户做了饭，不新增未画出的食材 |
| F2 小花盆 | 花盆、现成叶片和自己的观看偏好；“我总觉得这边更好看。” | 普通静态视角即可，不要求转盆。当前小苗不冒充圆润多肉，不编已经长高、开花或缺水 |
| F3 一起读书 | 舍不得放下、自己的猜测、喜欢回读；“这本我还想再看一会儿。” | 是当下意愿，不阻止用户结束。猜测只作为猜测，不新增已知情节，也不说用户读了多少 |
| F4 一杯茶 | 自己喝茶的习惯、杯子的顺手与短暂享受；“有时候捧着杯子，也没急着喝。” | 一般习惯不要求新增捧杯动作；当前只有一杯时不说“这杯给你”，不伪造另一杯或倒茶过程 |
| F5 吹泡泡 | 喜欢短暂的小玩意、还想试一颗的心情；“飞走就飞走，我还能吹。” | 泡泡确实呈现过才指这一次；表达自己，不借机教用户放下。不保证下一颗更大，不用用户点击维持泡泡 |
| F6 纸船 | 把纸变成东西的兴趣、自己的作品；“纸能折成船，我一直觉得挺神奇。” | 不要求新增折法或歪船；不能从纸船推断一起旅行，也不声称船已永久收集 |
| F7 积木塔 | 小作品里自己的取舍与一点自得；“就这么高。旗子得有。” | 低矮积木与旗真实存在；不要求增高或搭成城堡。未摆完时不提前用完成态口吻 |
| F8 看星星 | 看不全也能喜欢、对眼前星空的兴趣；“不用都认得，我也喜欢看。” | 指角色自己的看法，不扮演专业天文解说，不增加星座辨识、流星或未发生的许愿 |
| R1 伸个懒腰 | 一次身体舒展后的简短满足；“这一伸，舒服。” | 完整伸展已经发生且可感知才用当下说法；减少动态版不支持时改成一般偏好或无字 |
| R2 看云 | 懒洋洋的个人趣味；“云走它的，我坐我的。” | 适配已有看云情境，不要求云变成动物或按台词重画；不借云评价用户想法 |
| R3 暖暖的饮品 | 歇着、慢慢享用自己的饮品；“这一会儿，就慢慢喝。” | 不推断真实用户也在喝、不说饮品已经降到合适温度；与F4共享部分普通偏好，但避免连续重复 |

活泼与普通说法交错。有些活动适合一句小主意，有些只需要一句舒服的感受；不要求每句都令人发笑。真正的亲近另由明确回应和有事实依据的分享承担，不把每杯茶、每本书都改成送给用户的礼物。

## 9. 三段实际使用路径

**快速开始并被打断。** 打开 → 调成10分钟：功能位即可。开始 → 合适时一句陪伴。20秒后暂停 → 显示已暂停。留标记 → 如实确认。继续 → 显示计时中。即使用户十秒内操作了很多次，也不连播五句安慰，不把开始后暂停当成失败。

**专注结束后去休息。** 25分钟自然到期 → 时间与保存状态可见，可选一句收尾。用户立即点休息 → 保持真实休息状态，自动短句受同一降噪间隔，通常不再说一句。离开手机 → 无聊天继续。回来选“有点累了” → 立即给相应支持，不受自动降噪限制；类别不延续到下次主动打开。

**想亲近它，又突然需要记事。** 读书时点角色 → 有动作回应，正常专注默认不加文字。点“给我一句鼓励” → 完整读一句。打开想法编辑器 → 原句暂时让位、输入优先。保存返回 → 原句保留；保存失败 → 正确显示错误，不能用句子里“放好了”覆盖事实。关闭 → 安静，不问有没有好一些。

## 10. 写稿、接入与校验

一条新人物台词至少交代：**场景编号、交流目的、成立条件、可用阶段、展示方式、语义主题、稳定身份与版本。** 同时说明有无新物件／动作／输入要求，以及是否允许收藏或作为故事快照。身份与版本沿用既有内容机制；不是要求新增一套后台或重复维护数据库。

每个候选池应有表达角度的差异，而不只是同义词替换。普通话、具体看法与少量趣味交错；不预设精确的笑话概率。支持池需要接住请求；日常池可以聊偏好、观察、想象和自己的选择；收尾池要适合各种时长和未知的现实任务结果。

| 接入顺序 | 这一步解决什么 | 要补的工作 |
| --- | --- | --- |
| 对齐文档与资源 | 当前61句逐条对照，区分48句日常候选 | 本轮已完成逐句删改并同步09和24；其余场景样稿继续注明候选 |
| 调整现有语言节奏 | 暂停、想法等工具操作减少附加话；自动消息不密集 | 本轮已调整触发、共享降噪与显示寿命；固定状态、恢复、保存及故事资格沿原规则 |
| 改主动支持与选句 | 四类各自回应请求，有不同口吻与受约束的随机变化 | 精修后四类分别11／10／8／10句，更新版本并直接随机抽取；解析器不再固定池大小，保留适用性校验 |
| 再试触碰文字／日常宿主 | 少量新增关系表达和生活趣味 | 明确语义事件、注意力优先、静态替代与取消；未实现宿主的稿件继续留作候选 |
| 故事与物件最后接正式内容 | 让对白、结果与历史真正对应 | 完整章稿、事实条件、保存快照、版本与来源一起交付 |

检查时覆盖：连续快操作、零秒和短段结束、后台到期、完整一段无操作、主动换句、跨类别、输入与保存失败、触碰连点、旧收藏和历史重读、小屏大字与减少动态。具体目标见[语言验收](07-acceptance.md#test-copy)。

本轮文稿复核作了三处收紧：休息不等于想聊天；触碰不等于想阅读；好听的台词也不能代替固定状态。还单独检查了“接连操作不连播”“随机后不变人格”“刷新不产生新的业务事实”和“候选不冒充已上线”。这些是设计检查，不代表用户喜爱度测试。运行验证的实际范围单列于实现报告。
