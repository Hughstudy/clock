## 附录D　验收规格

本附录定义应执行的检查。每次发布按实际交付范围登记通过、未通过与未覆盖，附构建、设备及观察证据；本次仅整理文档，不声称完成应用验收。

T- 是独立的测试命名空间。用例描述目标行为，结果需在实际交付版本填写。动作编号使用 ACT-；两者通过正文规则及场景相连。

核心用例见D.1，日常操作与跨模块见D.8—D.11，制作、融合和首屏见D.12—D.15，奖励和文案见D.16—D.17。

### D.2 用户体验验证

第一轮邀请目标场景用户完成：直接开始5分钟、被打断后暂停、提前结束、记下想法、隔一段时间再回来，以及查看过去记录。观察是否需要解释、是否误会按钮和数字，再询问“哪一句让你有被催促或被评判的感觉”。不要求披露诊断，不通过一次测试判断健康或注意力水平。

分开观察**首次理解、熟悉后再用、内容已看过、缺席后重返**，不要求用户连续签到或为了试验每天使用。用同一任务、布局和计时，对照当前内容与更简单的表现，记录喜欢的具体细节、额外操作和干扰；不预设动画更多或更少更好。故事理解访谈面向愿意查看的体验者，不看、不记得或不喜欢同样记录，不能把会复述设定当作工具使用资格。模拟30次只能验证重复与状态，不证明长期喜欢；长期价值须等真实复用与自愿回访证据，不以短期点击和强迫回访代替。

**长期观察计划，待执行。** 先用固定首批内容进行2—4周的自愿复用观察，作为初轮计划而非长期有效性的证明；覆盖常用短段、常被打断、低频返回及主要只用工具的情境，不要求诊断、连续使用或披露便签正文。开始时记录自己的使用目的，熟悉或主动回访时记录再次使用／停止使用的原因，以及是否因故事改变时长、休息或查看频率。区分“任务已完成／暂不需要”与“无聊／受干扰／操作困难”，不把所有减少使用都判为失败，也不以打开更多判为成功。记录采用自愿反馈与经同意的观察，不因此新增后台行为采集。

单章原型只能证明局部可行；重复规则通过、愿意再看、真实任务中的多次复用分别记录。若重复内容无趣，先改本次动机与关键选择；若有趣但抢注意力，先减干扰；若用户希望换日常，再评审可选入口，不能直接增加签到、随机稀有奖或强制回访。

| **验证问题** | **可用证据** | **不应用作目标的指标** |
| --- | --- | --- |
| 开始是否足够轻 | 从首页到开始的动作数；可用性测试中的犹豫与误触。 | 强制更长专注或强制填任务后的完成率。 |
| 反馈是否温和 | 对暂停、短段结束、回来文案的原话反馈；是否感到必须照顾角色、完成任务才获认可或缺席后需要补偿。 | 鼓励点击次数、角色互动时长越多越好。 |
| 角色是否值得喜欢 | 在不新增解锁内容的熟悉场景里，询问角色想做什么、哪个细节值得再见；跨章核对是否像同一个伙伴。允许没注意、不喜欢，结合T-LIFE07／09记录原因。 | 盯屏更久、点击更多或必须说出预设性格词。 |
| 回来是否容易 | 恢复原状态是否成功；用户是否理解下一步。 | 不断签率、不能暂停的连续工作时间。 |
| 故事收集是否造成隐性压力 | 按5.2记录短章／完整章是否被理解为事实、收集条件是否清楚；保留不喜欢、无感与不同解释。没有未完事项可供补做。 | 为收集而延误休息、刷短段、误认短章等于失败或角色受损；不以用户会背规则代替体验证据。 |
| 所得是否有意义 | 自愿查看一项所得后，能否找到来由、再次查看或辨认后文使用；没有兴趣也是有效结果。结合T-R13区分喜欢内容与只想凑数量。 | 收藏数、摆设数、已完成图鉴比例越高越好。 |
| 记录是否可信 | 明细与总计可复算；短段、导入和跨设备备份结果。 | 把计时等同于效率，把分心记录少等同于改善。 |
| 记录是否看得懂、找得回 | 按D.19分别完成当天确认时间、日后找想法和重看旧故事；记录是否无需解释、路径与误解点，允许不需要回顾。可用合成便签，不要求隐私披露。 | 在记录页停留更久、打开更多次、清空全部待看或收藏更多。 |
| 是否愿意付费 | 在明确范围和平台的原型中测试购买意愿与拒绝理由。 | 从竞品存在或评分数量推断本产品收入。 |

### D.3 本地优先的验证

以下为待执行验收，按[C.1.1](04-data.md#data-format-contract)核对实际应用，不限定数据库：

| 情境 | 通过条件 |
| --- | --- |
| 核心资源准备完成后断网、关闭再打开 | 计时、写想法、回看及所需画面可用；无需网络读取个人数据 |
| 活动段／暂停段／已存草稿／正式记录分别重开 | 同一ID、原归属与合法状态恢复；已存草稿可找回，未确认写入不冒称已保存；关闭前回调不是唯一保存保障 |
| 写入中断、容量不足、保存回执迟到 | 不露出半份业务结果、不清新输入、不重复结算；按原规则显示失败或待核对 |
| 保存→导出→恢复→重开 | 字段类型、空值、文本、引用及统计符合原口径；备份中的活动段按C.7恢复为暂停，不能把备份间隔计入投入 |
| 应用内清理可重建资源／派生缓存，重新准备资源 | 清理不删除个人记录；资源缺失与历史缺失分开呈现，不能以缺图推断数据不存在 |

状态转换、删除撤销、重复操作、跨窗口与版本兼容继续执行D.20—D.24，不另建一套相冲突的测试口径。锁屏准点提醒单独验收，不以重开计时正确代替。

MVP 默认不加后台行为追踪。优先通过用户同意的观察、访谈和可选择导出的汇总验证。若以后增加遥测，应另写数据范围与用户选择，不把个人便签、任务文本或“疑似 ADHD”判断上传作为默认功能。

### D.4 视觉方案验收

最终视觉按[绘画规则](03-ui.md#drawing-rules)核验水墨、主角蓝、辅助色及空间接触；当前功能原型可保留现有画法，验证记录须注明阶段，不把原型通过当正式美术通过。手机尺寸下神态、时间与操作可辨。动作检查覆盖拿起、移动、停留、放下、暂停和中途结束的连续姿态；静态首尾图不能替代。

当前迭代使用蓝色伙伴，保持同一角色和任务比较两种入口布局。检查准备、运行、暂停、提前结束、想法暂存和小屏操作。若任务包含奖励回看，再验证相应入口与保存事实。旧U1／U2／U3及角色剪影比较保留为历史研究。

检查不看名称能否识别整体设计、短句是否像催促、暂停和短段结束是否同样被接纳、用户能否说出获得什么以及去哪找、角色是否挤占主操作，以及完全不互动时产品是否仍然可用。奖励验收另执行D.16的T-R01—T-R12。

### D.6 降噪与陪伴

以下为实际使用走查。需同时拿到完整界面状态、连续操作录屏和用户原话；只交一张简洁首屏不算合格。

| 编号 | 操作或检查 | 应观察到的结果 |
| --- | --- | --- |
| <a id="t-q01"></a>T-Q01 | 列出所有主界面与路由 | 只有专注、记录两个主页面与低频设置；各状态和详情不新增主页面 |
| <a id="t-q02"></a>T-Q02 | 完成开始、记录想法、暂停、继续、提前结束、休息 | 全程留在专注页；最多一层局部面板；无领奖页和连续弹窗 |
| <a id="t-q03"></a>T-Q03 | 查昨天某段与关联想法，再回计时 | 往返最多2次主页面切换；同一记录内可读，原会话状态不变 |
| <a id="t-q04"></a>T-Q04 | 查超过30天前的想法和收藏 | 能经内容选择器集中找到；不被近7天统计范围隐藏，不要求逐日翻页 |
| <a id="t-q05"></a>T-Q05 | 对照准备、运行、暂停、结束与休息五个首屏 | 主动作明确；必要入口可发现；不把所有状态的按钮一起铺开 |
| <a id="t-q06"></a>T-Q06 | 首屏有20条记录、长便签与多种奖励 | 首屏可认出一段回忆，点一次打开原记录，时间汇总次于回忆 |
| <a id="t-q07"></a>T-Q07 | 展开、编辑、收起条目，再切换内容模式 | 不堆叠面板，不丢草稿或阅读位置；长内容不遮主导航和关闭动作 |
| <a id="t-q08"></a>T-Q08 | 分别体验计时运行与主动探索，再减少动态 | 运行中无被动催看或无关动态争夺；主动探索允许丰富活跃的表达；静态版本仍保留性格、趣味与信息 |
| <a id="t-q09"></a>T-Q09 | 暂存成功、结束保存与新内容同时发生 | 事实与回应集中呈现，不连播toast、气泡和奖励卡；错误优先准确显示 |
| <a id="t-q10"></a>T-Q10 | 不点角色、不看收藏，使用三核心功能 | 不被打断、不漏必要信息，也不损失记录和已得内容 |
| <a id="t-q11"></a>T-Q11 | 操作中出现新记录、切页再回来、放大文字 | 当前阅读位置、计时状态和可达操作保留；布局不突然跳动 |
| <a id="t-q12"></a>T-Q12 | 与用户共同回看一个具体小情节 | 用户能说出喜欢或不适的具体细节；不靠“很治愈”四个字替代反馈 |
| <a id="t-q13"></a>T-Q13 | 同一角色分别呈现活跃与舒展版本 | 分开评价“喜欢程度、想看程度、是否打扰、是否感到被催促”；不预设越慢越治愈 |
| <a id="t-q14"></a>T-Q14 | 角色很开心时，用户立即暂停、结束或离开 | 情绪与已有奖励不被收回；用户没有必须回应、继续或看完的负担 |
| <a id="t-q15"></a>T-Q15 | 新角色与旧素材在相同构图中比较 | 按新目标评估功能与喜爱度，不因旧素材可复用就默认获选；保持证据与判断分开 |
| <a id="t-q16"></a>T-Q16 | 将同一轮廓与布局试配不同蓝色方案 | 比较角色识别、阅读与整体感受；蓝色不自动等于海洋、低饱和或低活力 |
| <a id="t-q17"></a>T-Q17 | 在叙事节点到来前分别打开便签输入、结束确认、主动鼓励阅读或可处理的恢复提示；保持原计时状态，跨节点后退出该操作 | 无关表演让位，输入、焦点和当前文字不被替换；时间、已达事实及必要错误照常更新。退出后显示最新可信落点，不补播队列、不重发所得、不新增会话；取消确认不结束计时 |

访谈用中性问题：“这屏第一眼看到了什么？”“刚才有没有想找但找不到的东西？”“哪一处让你觉得舒服、好笑或被打扰？”“哪个动作可以删掉？”也允许回答没有特别感受。出现“怕错过”“得点一下照顾它”“东西太多不想看”时，回到入口与反馈结构修改；觉得太平时，可以调整情节、表情、动作幅度、速度、构图或色彩；结合发生时机判断干扰，不把表现更活跃当成违规。

<a id="test-physics"></a>

### D.7 物理互动

适用范围：固定主控方案执行相关接触、取消及可用性检查。涉及真实控件位移或A/B/C比较的条目仅供隔离研究，不能作为首批交付门槛。

| 编号 | 场景 | 合格结果 |
| --- | --- | --- |
| <a id="t-ph01"></a>T-PH01 | 慢放查看接近、接触、最大受力和回稳 | 接触点、受力方向、遮挡、角色重心一致；没有隔空碰撞或穿透 |
| <a id="t-ph02"></a>T-PH02 | 对比软按钮外壳、薄便签与较硬边界 | 材质反应可辨；不把所有元素做成同一种抖动 |
| <a id="t-ph03"></a>T-PH03 | 开始动画中立即暂停，再继续 | 按真实动作处理，计时不等动画；旧情节取消、不覆盖新状态 |
| <a id="t-ph04"></a>T-PH04 | 装饰覆盖区域反复点击、两标签页结束同一段 | 装饰不吃点击；真实操作可达，记录与奖励只结算一次 |
| <a id="t-ph05"></a>T-PH05 | 主按钮被压凹时点击边缘；用键盘触发 | 视觉/命中一致，名称、焦点与按钮语义清楚；不用猜真正点击点 |
| <a id="t-ph06"></a>T-PH06 | 测试真实搬动备选，指针悬停/按下或键盘聚焦 | 不挪走正在操作的按钮、不追按钮；不合格即回退固定接触方案 |
| <a id="t-ph07"></a>T-PH07 | 计时图形受力时核对数字与比例 | 时间读数和语义不变，暂停时不表达继续流逝 |
