## 附录E　内容资产与制作规格

文案键、使用条件及章稿交接模板供实际制作复用。明确标为草案或样例的内容不自动进入交付；采用范围由正文第五章决定。

### E.1 说话的角色与语气

沿用[伙伴关系](01-product.md#relationship)：平等、懂分寸，有自己的兴趣，也能回应用户。说话使用自然的成年人日常语言，不幼儿化、不说教、不喊口号或连续感叹，也不要求用户照顾角色情绪。支持只是角色的一种表达，不把所有日常都写成鼓励用户努力；清楚回应或安静在场同样成立。功能事实、用户主动表达与角色自身故事的依据按[A.4](02-features.md#response-basis)分开；角色日常言行还须对照[共用创作基准](10-character.md#character-basis)，不能由不同章节各写一套人格。

新增深层语气要让用户感到：自己的在意、善意、需要和仍待展开的可能，值得被认真看见。借鉴共情表达中的耐心、尊重和善意，产品角色仍是一位温柔同伴，不以咨询师身份分析用户。优先把话落在用户明确表达或主动做出的选择上，也可以表达对人的完整价值的尊重；不凭计时行为断言人格、往事或隐藏情绪。

“我”只表示应用中的陪伴角色，可以说“我陪你做这一小段”；不预设鲸鱼、猫、人形、性别或名字。“我们”只指当前共同经历，不发展成依赖关系。既要有“轻轻鼓个掌”的小小欣喜，也要允许一句安静的“好，我们接着这里”。

| 要做到 | 具体写法 | 写作边界 |
| --- | --- | --- |
| 肯定真实动作 | 愿意开始、按下暂停、记下想法、回来继续 | 不把点开计时器说成完成任务、自律提升或战胜症状 |
| 平等接纳不同节奏 | 手动结束和到时结束共用同一结束池 | 不用“虽然只有”“至少还”“终于坚持完”分出高低 |
| 给选择留空间 | 可以、想……时、按你的节奏 | 不在鼓励后接“所以再做一段”“别让我失望” |
| 温和而有生命力 | 少量自然拟人或轻快动作词 | 不每句都堆可爱语气词，不用宝宝、乖、主人等称呼 |
| 保持可信 | 情绪句负责支持，状态文字负责事实 | 未保存不说收好了；未知心情不说“我知道你很累” |

节点短句和轻量鼓励默认一到两行；深层共情允许一到两句完整表达，在375宽度、正常字号下以二到四行为初始排版目标。主动鼓励在既有阅读区域内完整呈现，长内容在面板内滚动；大字号可增加行数，不截断、不缩小字号。不要为了凑行数删掉承接情绪或保留选择的后半句。全库默认不使用表情符号、不逐字打字、不每句加感叹号；角色姿态和标点共同保持轻松。

### E.2 触发、优先级与轮换

**触发顺序：先确认业务状态，再筛选适用文案，最后决定是否显示鼓励。** 不根据未使用天数、分心次数、停留时长或便签内容推测情绪。先有真实成功结果，才可使用含“记下”“收好”“留下”的话语。

| 情况 | 显示规则 |
| --- | --- |
| 数据错误或状态未知 | 先显示对应技术事实与下一步；取消与之冲突的成功庆祝，不用表扬盖住问题 |
| 用户主动要鼓励 | 立即给ASKG一句，可换句、收藏；可选类别只用于本次请求，不能暗中建立情绪档案 |
| 新会话开始、专注结束、休息开始或结束 | 每个真实状态事件最多一句；开始与立即结束可各有一句，但原地替换，不排队；短段不取消应有的温和收尾 |
| 暂停、继续、暂存、返回 | 首次动作可给一句；30秒内连续同类交互默认只留准确、温和的功能文字。30秒是初始降噪建议，可通过试用调整 |
| 同一次“记下并返回” | 保存回应与返回回应最多选一条；保存失败只讲失败，返回不暗示保存成功 |
| 同次开始、生成纪念、解锁新内容 | 开始只一句；纪念以页面状态承接；新内容留到本段结束或主动查看，不连弹三条 |
| 再打开、刷新、多窗口同步 | 恢复真实状态，不重播开始、发奖和到时鼓励；仍运行或暂停时不再说“开始一段吧” |
| 回顾、空状态、纪念详情 | 属于静态页面话语，不自动播报成连串气泡；滚动、筛选和切页不抽新句 |
| 节点鼓励关闭 | 使用固定状态文案；主动“给我一句鼓励”仍可用；不以奖励方式诱导重新开启 |
| 没有发生动作 | 不定时推送“加油”，不因倒计时过半突然搭话，也不催回访 |
| 正在输入、确认、处理恢复或主动阅读 | 依[B.4](03-ui.md#attention-policy)让无关叙事动作退为静姿；保留实际操作反馈，退出后不补播错过表演 |

**轮换：** 节点池先使用编号01作为首选，随后按本地轮换次序用完再循环。四个主动池均保留01为初次首选；短句01—08与深层句09—14交替，初始次序为01、09、02、10、03、11、04、12、05、13、06、14、07、08，用完再循环。这是内容编排建议，不是稀有度或解锁顺序；每句从首次使用起均可直接换到。同池相邻两次不重复。切换页面不重抽，页面重建沿用当前句。用户主动“换一句”立即前进一条，不受庆祝动画冷却影响；文字没有次数额度，也没有稀有句概率。

跨池若连续两句表达过于接近，例如“按你的节奏”紧跟“节奏由你来定”，优先换成该池另一句。实现可用语义标签做简单避让，不能为此引入在线模型。无法找到合适新句时，用准确的功能文字；不为了凑一句话捏造事实。

**显示时长：** 2—4秒是节点短反馈的初始参考，不是所有角色内容的时长上限，也不要求文字一起消失。用户主动展开的内容按自身阅读和叙事需要设计，可随时退出。节点短句放在固定且不遮操作的位置，保留到下一次动作、切页或主动关闭；主动请求的短句保留到换句或关闭，给收藏与阅读留出时间。辅助技术只播报新操作结果一次，不逐秒读倒计时。角色不因用户没读或没回应而催促。

### E.5 技术异常也要温和、准确

“全部正面”指不评价和惩罚用户，不表示隐藏技术失败。异常提示是系统事实，不让角色哭泣、责怪用户或承诺绝不会丢失。以下文字只在右侧条件真实成立时使用；按钮仅在相应能力已实现时出现。

| 编号 | 场景 | 提示文字 | 建议动作 | 真实性条件 |
| --- | --- | --- | --- | --- |
| ERR01 | 记录写入失败 | 这次记录还没保存成功，可以重试。 | 重试保存 | 仅说明实际失败；内存结果继续保留，不能庆祝已保存。 |
| ERR02 | 历史读取失败 | 暂时无法读取历史，可以重试。 | 重试读取 | 保留原文；不把历史显示为0，不套普通空状态。 |
| ERR03 | 应用数据版本更新 | 这些记录来自更新的版本，更新应用后再试。 | 查看更新说明 | 只有确认数据版本不受支持时使用；不承诺更新一定成功。 |
| ERR04 | 想法文字写入失败 | 这条想法还没保存成功，文字暂留在当前页面。 | 重试保存 | 必须确认草稿确实还在；提示离开可能丢失未保存内容，不能称已备份。 |
| ERR05 | 空标记写入失败 | 这个标记还没记下来，可以重试。 | 重试记录 | 重试沿用原ID，不重复计数。 |
| ERR06 | 备份文件无效 | 这个文件暂时无法导入，请选择本应用导出的完整备份。 | 重新选文件 | 仅用于格式或结构校验不通过；未修改现有数据。 |
| ERR07 | 备份版本较新 | 备份版本较新，请更新应用后再试。 | 查看更新说明 | 与无效文件分开，保留待恢复文件。 |
| ERR08 | 导出失败 | 备份还没生成成功，可以重试。 | 重新导出 | 不得显示“已备份”或分享不存在的文件。 |
| ERR09 | 替换恢复失败且已回滚 | 恢复未完成，原有数据保持不变。 | 重新尝试 | 仅在验证原数据未改变或回滚成功时使用；状态不明则准确说明无法确认结果。 |
| ERR10 | 全量清理未能确认完成 | 清理还没完成，暂时无法确认全部删除。 | 重试清理 | 不称“已全部清空”；不追加角色挽留。 |
| ERR11 | 专注时长输入无效 | 专注时长可以设为1到120之间的整数分钟。 | 恢复上次值 | 休息时长分别使用自身范围，不能复用120这个上限。 |
| ERR12 | 提示音无法播放 | 提示音暂时无法播放。 | 检查声音设置 | 计时状态独立显示；不能在到时后谎称仍在继续，不自动反复响铃。 |
| ERR13 | 新内容写入失败 | 这份内容还没保存成功，可以重试。 | 重试保存 | 待发奖励用原ID恢复，不宣布永久获得。 |
| ERR14 | 收藏短句失败 | 这句话还没收藏成功，可以重试。 | 重试收藏 | 不提前显示“已收藏”。 |

短休息输入无效时固定使用“短休息可以设为1到60之间的整数分钟。”；长休息使用“长休息可以设为1到90之间的整数分钟。”。所有范围随正式参数同步更新，不把数字散落在无法维护的文本中。

### E.6 欢迎短笺、收藏与重读

**欢迎短笺首选稿：**

> 很高兴在这里见到你。选一小段时间，做眼前的一小件事。想暂停、想休息，都可以按自己的节奏来。每一次愿意开始，都值得被温柔地记住。

欢迎短笺是一份可忽略、以后能重读的内容；首次首屏只显示WEL一句，不强制读完短笺再开始。短笺可以出现在收藏中，未读不加红点，不设置领取任务。

**收藏规则：** 用户主动收藏自己喜欢的鼓励句，默认不自动收藏所有出现过的话。相同句子只存一份；“已收藏”只有保存成功才出现，取消收藏无需解释原因。在记录页收藏内容区重读不改计时、参与数或奖励，关闭节点鼓励后仍能查看。欢迎笺、已获长期内容与主动句子收藏的动作权限按[A.4](02-features.md#collection-kinds)区分，不因同区显示套用相同取消／删除文案。

收藏保存稳定文案ID、所选文本快照和文案版本。以后修订某句话，不静默改写用户已经收藏的文字；可在更新说明中说明变化。备份导出与恢复保留这些字段。用户选择的疲惫等类别不单独留作情绪档案；收藏文本本身属于用户选择保留的内容，可删除，全量清理一并删除。

### E.7 禁用表达与替代方向

| 不使用的表达 | 问题 | 可用替代或处理 |
| --- | --- | --- |
| 你终于开始了 | 暗含此前拖延和责备 | 开始了，我陪你做这一小段。 |
| 虽然只有1分钟，也算努力了 | 把短段放在低一级 | 谢谢你给自己这一小段时间。 |
| 再坚持一下，别放弃 | 把暂停和结束当成失败 | 就停在这里，下一步由你选。 |
| 今天怎么又走神了 | 评价用户且把主动记录当缺点 | 想法放好了，之后随时能看。 |
| 你已经完成任务，效率真高 | 计时不证明任务完成或效率 | 本段计时{elapsed}。 |
| 我知道你今天很累 | 未经用户表达就推断状态 | 默认使用ASKG；用户主动选择后才使用ASKT |
| 休息是奖励给完成任务的你 | 限制休息资格 | 现在，安心歇一会儿吧。 |
| 我等了你好久，别再离开了 | 缺席负担和关系绑缚 | 欢迎回来，从现在这一刻开始就好。 |
| 超过了90%的人 | 无依据比较、引入排名 | 你的节奏，值得被认真了解。 |
| 已保存，放心离开吧 | 保存未知或失败时的假保证 | 使用对应ERR文字，说明可确认的实际状态 |
| 获得稀有鼓励，再来抽一次 | 让支持变成随机诱导 | 所有基础鼓励直接可用，换句不耗费任何资源 |
| 宝宝真乖，主人好棒 | 未经选择的幼儿化或服从关系 | 用自然成人语言肯定具体动作 |
| 我看穿了你坚强背后的孤独 | 把未知经历写成读心结论 | 对用户明确选择的状态作回应，不补写往事 |
| 你一定会成功，你有无限潜能 | 把支持变成结果保证，也可能变成新的期待 | 有些可能性，需要在适合你的节奏里，才慢慢显露出来。 |
| 真正善良的人都会继续努力 | 用美好品质换取继续使用或产出 | 肯定不附带下一段、坚持或回访要求 |
| 多专注一些，我就更喜欢你 | 把关系与关爱作为成绩回报 | 新内容说明新增经历，不宣告用户因此更值得被喜欢 |

不是机械封禁“没有”“失败”等字面词。技术异常必须准确说明；审阅重点是句子有没有评价用户、制造关系负担、伪造事实或剥夺选择。

### E.8 连续使用时的三条实际串联

下表用于检查相邻话语是否自然、是否重复，不能当成必须全播的剧情。功能状态始终清楚；节点鼓励关闭后只保留中间一列。

| 路径与动作 | 固定状态或结果 | 可用鼓励 |
| --- | --- | --- |
| 路径一：第一次打开 | 25分钟已选，可直接开始或改选 | WEL01：很高兴见到你，先做一点也很好。 |
| 点开始 | 计时中 | STA01：开始了，我陪你做这一小段。 |
| 20秒后结束并保存 | 本段计时20秒。 | END01：谢谢你给自己这一小段时间。 |
| 主动休息 | 休息计时中 | BRK01：现在，安心歇一会儿吧。 |
| 路径二：运行中点留个标记 | 已记下一个标记。 | NME01：先留个记号，想补充时再说。 |
| 紧接着加字保存并返回 | 想法已保存。 | 已有回应时不再连播NTX和BCK；回到原计时状态即可 |
| 之后主动要一句鼓励 | 给我一句鼓励 | ASKG03：给自己一点耐心，也是一种支持。 |
| 路径三：专注暂停后隔一段时间重开 | 上次专注已暂停，可以继续或结束。 | 不重播欢迎、开始和发奖 |
| 用户主动继续 | 计时中 | RES02：从刚才停下的地方继续就好。 |
| 到时结束并保存 | 本段计时25分钟。 | 同样可用END01，不换成“终于完成”的升级表扬 |

新的节点反馈可在原位置替换自动短句。用户主动打开阅读的句子由用户换句或关闭，新的计时事实更新到状态位。保存时仅有0秒则使用UI31与ZER，不使用“这一小段时间”的END。

### E.9 新增和修订文案的操作规范

开发遇到现有句库没有覆盖的状态时，先核对实际操作、目标对象、可证实的结果及可执行的下一步。同一含义优先复用内容资产（附录E）的现有编号和项目文案资源。已有动作需要新的按钮、状态、空态、错误或辅助阅读名称时，开发者可直接按本节撰写、校核并随功能交付。此流程发生在开发阶段，应用使用随版本发布的本地文案。

**先分清这句话承担什么职责。** 按钮告诉用户点下去会发生什么，状态告诉用户现在怎样，结果说明刚才完成了什么。鼓励回应人的选择，错误说明出了什么事及还能怎么做。使用日常成人中文，尽量一个短句表达一个意思。同一个对象在入口、面板、成功提示和记录页中沿用同一称呼。

| 类型 | 写法及可用示例 | 写入前核对 |
| --- | --- | --- |
| 导航、选择、执行 | 「记录」去历史页。「5分钟」选择本段时长。「开始专注」才确认并启动 | 看标签能预测去哪里、是否开始、作用于本次还是设置默认值 |
| 输入与关闭 | “记下想法”“补充文字”“保存想法” | 明确新建还是编辑、操作的对象。只有草稿可恢复时才显示相应恢复提示 |
| 状态与结果 | “已暂停”“正在保存想法…”“想法已保存” | 区分会话状态与本次写入结果。“已保存”只在该对象写入成功后出现 |
| 空态与未知 | 确认没有条目时可写“还没有想法”，筛选无结果时可写“这几天没有想法” | 读取失败使用对应错误事实，不能用空态或零值代替 |
| 错误与下一步 | “这条想法还没保存成功”。仅在支持重试时提供“重试保存” | 核对受影响对象、当前数据可用范围和恢复能力。只有能确认文字仍在时才补充“文字还在这里” |
| 鼓励与角色回应 | 暂停时可用“想继续的时候，再回来就好”一类短句 | 默认先查既有适用句。接纳休息和提前结束，仅在用户主动表达后回应特定情绪，不推断诊断、人格、效率或任务完成 |
| 确认与读屏 | 确认标题用“结束本次专注？”，按钮用“确认结束”“返回计时”。撤销使用“撤销标记”，可访问名称可补充指定对象 | 同一动作的可见与读屏名称相符。说清有影响的对象或后果，读屏只播报一次有意义的结果 |

**出现、停留和退出也是文案的一部分。** 页面契约统一见[B.5](03-ui.md#feedback-lifecycle)；每条动态文字都有对象、明确触发、事实条件、所属区域、退出／替换后的去向及播报方式。常态及动作词优先一行，普通反馈以手机正常字号一到两行为目标。先删重复解释，重要事实和可恢复动作完整保留。长说明、主动请求的长鼓励进单层可读区域。按320、375、430宽度、200%文字和软键盘复查，不能靠截断、缩字号或挪走按钮容纳新句。

| 同时有多条文字 | 显示与退出 |
| --- | --- |
| 普通成功或自动节点鼓励 | 对应结果原位更新，可短暂显示后退出。相同操作不重复播报，稍后不补播历史鼓励 |
| 待保存、失败、可撤销操作 | 恢复状态可查，重试绑定原操作。带行动的提示保留可操作机会。若撤销本身有期限，界面按真实能力提供后续查看或管理路径 |
| 用户正在输入或主动读鼓励 | 保留文字、键盘、焦点与所读句子。相关错误在对应位置可见；必要状态不遮挡输入。用户主动请求的支持可与技术事实并存 |

**复用与改写的边界。** 同一状态、同一动作、同一对象已有中文时，先复用B.6定稿条目。新功能含义不同，即使只差几个字也要区分。本版已定的名称直接执行；后续证据确需更名时，作为新修订统一更新正文、可见标签、读屏和用例，不在开发中自行并列旧名或恢复候选。功能短句进入项目已有的本地文案资源；鼓励沿用现有语料、事实筛选与版本机制。

**场景文案。** 优先让动作讲明白伙伴的动机和正在发生的事，不把每个故事改成对用户的赞美或劝勉。需要文字时可写“伙伴把书签夹好”，用户看到这句也可以直接离开。读书场景不写“你又读完了一章”，真实结果另用“本段计时{elapsed}”。退出、休息、缺席后返回都不触发“就差一点”“小屋等了你好久”等剧情。剧情标题不复用“已保存”“已获得”等表达数据结果的文案。

**开发时的最小记录。** 使用现有文案资源和命名约定。只有找不到可复用条目才新增稳定的键。把“键／显示文字／何时出现／证明它成立的状态／放在哪里／怎样退出或恢复”补在现有资源、测试说明或本次变更说明的合适位置；不要求另建一张重复维护的表。金额、时长、数量、范围等变量来自真实值并带单位。敏感便签与当前小步骤只在用户选择查看的应用区域内展示。

例：为“保存想法”补一句反馈时，保存请求发出可显示“正在保存想法…”。成功回执且对象相符，原位替换为“想法已保存”。写入失败则显示“这条想法还没保存成功”，保留可用的重试入口。三句共用原区域，只有终态播报一次相应结果。打开或关闭编辑器不能触发成功句；稍后到达的旧回执不能标记新的草稿已保存。

**可自行决定的范围。** 已有功能的准确短标签、结果、空态、辅助名称和事实明确的错误可自行补齐。若一句话意味着新增备份能力、永久保存、奖励资格、统计口径、删除后可恢复或新的情绪判断，先核查产品规则与实际能力。未定的承诺回到产品决策表，当前界面使用能证实的表述。新写鼓励先作为候选，沿用内容资产（附录E）的适用状态与评审流程，已编号的136句及用户已收藏的原文保持可追溯。

**写完后自检。** 第一次使用的人能否说出点击结果？对象和事实是否准确？失败、未知或快速重试时还成立吗？是否让暂停、休息或提前结束带上亏欠感？最窄屏和放大文字时，主按钮还在原处吗？任一项答不出，先修正文案或触发条件，再接入页面。

验收见[文案检查](07-acceptance.md#test-copy)。
