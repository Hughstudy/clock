## 附录C　逻辑数据、字段与动作映射

这里定义要保存什么、含义与格式、操作怎样影响数据、怎样恢复及验收。数据库、框架、物理表和离线资源机制由开发确定；引用表名是逻辑对照，不要求相同物理组织。

### C.1 职责、分层与边界

下表区分信息性质与保存责任，不新增运行状态或界面入口。

| 信息性质 | 典型内容 | 保存与恢复责任 |
| --- | --- | --- |
| 业务事实及必要当前状态 | 参与与结束记录、正式想法、故事检查点／终态、已收集生活事实、收藏、活动会话、有效偏好 | 按对象规则保存；属于已实现的个人数据时纳入备份。已结束的未完故事不建立待续对象 |
| 可恢复但未正式提交的输入 | 想法草稿、待确认的本次结果／修改 | 草稿按A.2保存并纳入已提交备份；其他待存副本如实标状态，不冒充已存事实 |
| 本次查看与交互上下文 | 未开始准备值、查看模式／位置、编辑作用域、输入序号、当前请求与在途意图 | 不改业务历史；仅协调本次异步操作，不另建行为日志表、不进便携备份。想法正文只有已提交草稿部分按原规则持久保存 |
| 派生数据与读取辅助 | 汇总、日趋势、分页边界、查询缓存 | 可由可信事实重算；可失效，不作为另一份历史或个人备份类别 |
| 版本化内容资源 | 章稿、图片、声音、文案目录 | 随离线资源提供；用户已收藏文本与故事摘要另按快照规则保存 |

**隐私与控制。** 核心体验本地优先、无需自建账号。不从便签、时长或记录次数推断人格、情绪、注意力或疾病；用户便签和小步骤不用于选章、改写故事。本版不新增后台采集、云同步或账号体系，也不把“本地保存”表述为已实现加密、永久保存或跨设备同步。删除与外部备份的控制范围见C.7。

<a id="data-format-contract"></a>

#### C.1.1 逻辑存储格式与交互对应

**数据库、框架、物理表及文件组织由开发确定。** 本文约定数据怎样表达、何时保存及操作结果；同一数据只有一份权威来源。内部实现可等价映射，必须无损保留字段含义、身份、关联与恢复能力。

**字段格式。** 记录用具名字段表达，多条记录以稳定ID识别；文本为Unicode，状态用明确枚举，时间与时长按字段使用整数毫秒，日期键与原时区分开。`NULL`、空串、0及无记录分别解释；嵌套状态使用有版本、有限定键的结构。具体值域、默认、条件空值及可修改时点只在[C.9.3](05-data-fields.md#database-field-contract)定义，避免另立口径。

| 数据类别 | 逻辑保存形式与寿命 | 对应交互及关键验证 |
| --- | --- | --- |
| 计时与正式内容 | 按稳定ID保存会话、想法、故事与收藏；偏好保存当前生效值，历史快照冻结 | 开始／暂停／继续／结束、编辑／收藏／改设置；重试不重复，状态转换与字段成组一致。见[D.20](07-acceptance.md#data-contract-tests)、[D.23](07-acceptance.md#field-tests) |
| 可恢复草稿 | 与正式想法分开的单草稿记录，保留文本、原归属、编辑目标与版本 | 输入中保存，关闭仍可恢复；明确保存才转正式，迟到回执不清新字。见[D.22](07-acceptance.md#frontend-db-tests) |
| 删除撤销 | 按条目与删除版本保存短期原文和截止时刻；到期移除原文，保留必要删除标识 | 删除、撤销、重开、导出；10分钟不续期，备份不带撤销原文。见[T-DATA09—10](07-acceptance.md#t-data09) |
| 临时交互与派生结果 | 弹窗、未开始选择、动画、查询缓存不作用户历史；汇总从权威记录重算 | 切页、改筛选、关闭和重开不能新增业务事实；丢弃临时状态不丢已存草稿。见[D.24](07-acceptance.md#action-completeness-tests) |
| 内容资源与备份 | 图片／声音／章稿以资源ID与版本引用；个人备份为带格式版本的UTF-8 JSON，含声明支持的已提交数据 | 断网可用；导出／恢复校验类型、空值、引用和版本，失败保留原数据。见[C.7](#backup)、[D.3](07-acceptance.md#test-local) |

月份、想法查询与物件来由只增加读取组织；综合场景使用world_state中的初始／已收集状态，新增变化只沿符合收集条件的到期事务写入。逻辑格式、资源映射、缓存及旧记录兼容见[C.9.6.1](05-data-fields.md#record-read-contract)，不指定数据库或全文索引引擎。

每项交互均须对应“前置状态 → 读取依据 → 写入或明确不写入 → 成功／失败／取消结果 → 重开恢复”。逐项复用[动作映射](06-data-commands.md#action-field-matrix)与[D.24](07-acceptance.md#action-completeness-tests)；测试检查结果及不变量，不要求某种数据库或物理表数。

<a id="data-objects"></a>

### C.2 逻辑对象、身份与数据关系

**一次计时一个会话身份，从开始到结束不换表、不换ID。** 参与数读取有可靠开始依据的专注集合，结束次数和计时读取终态集合；不再各维护一份会话副本。旧记录缺开始依据时保留未知，不从结束记录补造参与。以下是逻辑数据对象概览；参考表名用于定位字段，不要求生产实现使用相同物理表数。完整字段与约束见[对应规格](05-data-fields.md#database-dictionary)。

| 底表／对象 | 一行表示什么 | 身份、关联与保留边界 |
| --- | --- | --- |
| `db_meta`／`app_preferences` | 当前数据世代／一份已生效偏好，各为单例 | 结构版本、世代和提交序号分开；偏好不混入未开始选择和浏览位置 |
| `sessions` | 一次会话从明确开始到结束的事实 | `session_id`主键；至多一个活动段。参与/结束是不同读取集合，休息不进入专注指标 |
| `notes` | 一个正式想法或空记号 | `note_id`主键；可选`session_id`指向一个专注；独立想法不虚构所属。删除标识与空记号不同 |
| `note_drafts`／`note_undo` | 一份可恢复输入／某条删除的短期撤销原文 | 草稿为单例、edit绑定原条目及基础版本；撤销原文按原10分钟窗口隔离，不进入正式想法或永久历史 |
| `story_items` | 一次会话内的小事尝试 | 稳定item_id不等于DAY题材ID；新段新实例，结束后关闭，不跨段接续 |
| `session_stories` | 某会话的绑定、入场、检查点及终态 | session_id主键兼外键，一会话至多一份；与本段item_id关联，终态冻结且不嵌便签正文 |
| `story_continuation`（退役） | 不再属于本版运行对象 | 不新增、消费或恢复为待办；旧版真实数据按C.9.7保护与映射，不能静默删除 |
| `world_state`／`story_rotation` | 当前有界事实/布景／目录轮换位置 | 世界与历史快照分开；版本化有界JSON只存已定义内容状态，不装整份用户历史；游标随成功绑定提交 |
| `quote_favorites` | 一个稳定句子的主动收藏关系及当时文本 | 按句子ID唯一；取消关系不删故事或资格，文本按收藏时版本保存 |
| `content_grants` | 一项实际可证明的已获内容资格 | 按内容ID唯一；只承接已交付事实，不启用未来阈值、商城或欢迎笺收藏关系 |
| `mutation_receipts` | 原操作已提交的最小技术依据 | `(data_epoch, op_id)`唯一；不存便签正文、情绪档案或完整旧快照；不是事件溯源/分析日志 |

**字段约定。** 稳定ID不由列表序号生成；时间用整数毫秒，日期键与时区依据分开；未知为NULL，不以0或现在时间代填。新数据须满足完整约束，旧数据兼容仅由受控迁移入口使用。对象修订用于冲突判断，数据世代用于隔离替换/清空，内容版本用于解释旧剧情；三者不互相替代。

<a id="data-field-rules"></a>

**字段契约（）。** 每列按“值域/单位 → 新建依据 → 条件NULL → 唯一写入方 → 可变与冻结时点 → 关联约束 → 导入/删除”解释，完整字典见[C.9.3](05-data-fields.md#database-field-contract)。运行/暂停/结束、new/edit草稿、空记号/删除必须满足整组字段条件；SQL允许NULL不代表所有状态可空，DEFAULT不用于修补残缺备份。业务行内容不变不递增row_revision；技术回执可以改变commit_seq但不增加用户指标。输入序号、控件作用域、等待/失败提示仍属临时协调信息，不新增持久列。

**关系与读取。** 一段专注可以有多条想法，每条想法只有一个明确归属或独立存在；一段可以没有故事，不能为了关联完整而编造。会话读当时计时事实，故事读当时快照，想法读同ID最新合法正文与删除状态，收藏句子读收藏时文本。记录页只组合这些对象，不保存整页副本，不把伙伴行为写成用户任务。

**不单独建业务底表的内容。** 累计时长、参与数、日趋势、物件来由索引与分页均可从可信事实和版本化目录重算；月份、搜索词、昼夜预览和浏览位置仅为当前访问上下文。当前已收集生活事实仍由world_state保存；欢迎笺及物件／昼夜素材目录是版本化资源。`content_grants`的空槽位不扩大本期，其他尚未交付能力不能因字典中有对应对象就被标记为已实现。

### C.3 指标、日期与计算口径

#### C.3.1 统计对象与保存依据

**RULE-TOTAL · 同样本、同范围、同保存依据。** 正式汇总策略：只纳入已确认保存、可核对的记录。活动会话、休息、待保存或仅本次可用的结束结果不进入正式已存专注合计，应分别说明；保存或重读核验成功后按原ID纳入一次。已存数值为0而仍有待存结果时，不能显示成从未开始。

`W`是明确的归档日期范围；`E_W`是归档日期在W内、已确认保存的不同已结束专注会话。指标使用同一已提交依据，按所需字段判断可计算性。W如何由近7／30天及设备日期得到、何时刷新，统一见[A.5.7.2](02-features.md#review-window)，不改变历史日期键。

<a id="record-metrics"></a>

#### C.3.2 指标字典

| 量 | 目的、样本与算法 | 解释边界 |
| --- | --- | --- |
| 累计计时 `T_W` | `Σ(s∈E_W) 有效毫秒(s)`，回答范围内记录了多少已结束运行时间 | 排除暂停；0秒贡献0，不按便签数、故事数或已加载行数累加 |
| 已结束段数 `N_W` | E_W中不同会话ID数，用于核对时间来自多少段 | 可只作内部校核量，不默认进入首屏，不等于参与数 |
| 自然到期 `C_W`／手动结束 `M_W` | 按E_W中可信结束原因分类计数 | 不按故事是否收束、时长接近目标或用户任务是否完成推断 |
| 参与数 `P_W`／参与日数 `D_W` | 原参与日期在W内的不同已保存专注开始事件；日数按这些日期去重 | 可包含活动段；不作T_W分母，不要求与结束数量逐日相等 |
| 想法数（确需展示时） | 对明确想法范围内未删除、已保存条目按ID去重 | 包含空记号，排除草稿；所属与独立不重复计数，不是分心次数 |
| 主动收藏句数（确需展示时） | 仅对有效主动句子收藏关系计数 | 不把欢迎笺、已获内容及会话纪念计作主动收藏 |

这些是定义和校核量，不是新增首屏字段、评分、平均值或完成率。所有适用视图使用相同对象和计算依据；业务变更确认后的影响见C.4，读取一致性见C.5。

#### C.3.3 日期、缺失值与显示

**日期策略沿用现行定义。** 专注结束记录按会话开始时区中的结束日归档：自然到期取截止时刻，手动结束取确认时刻，不拆分跨午夜时长。参与按原开始事件在该会话开始时区的日期取样。历史日期键固定，不因查看、导入或旅行而重算。想法按自身创建时间／日期访问，编辑不改变创建日期；对象归属不因两个入口显示的日期不同而变化。

**缺失按字段处理。** 结束原因未知但结束、时长和归档日可信的旧专注可进入相应集合，原因归`U_W`；新结束记录仍须有明确原因。缺时长不能报完整时长合计；缺归档日不能保证窗口成员完整；缺可靠开始信息或参与日期不猜参与分日，仍保留已知全量参与事实。缺故事图、便签保存失败或故事字段缺失，不使可信计时失效。

**显示策略沿用现行定义。** 先对原始毫秒求和再格式化：正值不足1秒显示「不到1秒」，其他实际计时向下取整到秒，剩余倒计时向上取整到秒；0毫秒保留真实开始事实。逐条显示值相加不要求等于合计格式化后的值。范围完整核对且无匹配记录才能报零；未知缺口不能填零。

<a id="metric-relations"></a>

#### C.3.4 关系与复算约束

同一W、同一已提交依据下，`T_W＝Σ(日∈W)T_日`，`N_W＝C_W＋M_W＋U_W`。U只处理可信旧记录的未知原因，不是新会话的一种结束方式。参与集合和结束集合不同，不要求`P_W＝N_W`，不据此派生完成率或表现评分。

会话关联多条想法后仍只累计一次时长；故事跨段也不合并会话。想法的「待看／已收起」与「有正文／空记号」是两个独立维度；字段完整时各维分别合计等于同范围想法总数，不能将四组相加。收起或补字不改总数，删除确认与有效撤销才改变相应集合；旧分类未知不补标签。

指标、日趋势与明细必须可按同一依据复算；可信聚合可以覆盖尚未全部渲染的明细，已加载几行本身却不能证明全量。如何选择首屏字段、命名和交互仍由[A.5.7](02-features.md#records-ui)及[5.2](01-product.md#record-decisions)决定。

<a id="data-mutations"></a>

### C.4 数据变更、联动与提交边界

**业务事件只生效一次。** 功能规格（附录A）决定动作是否成立；本节列其数据影响。每次变更按[提交协议](05-data-fields.md#database-transactions)核对原操作、对象ID、对象版本与数据世代；业务写入、提交序号和最小回执在同一事务确认。先核对已发生事实及截止点，再处理仍有效命令。操作去重不能替代同一会话唯一开始／结束的对象约束。

| 已接受的动作或事件 | 同一变更应保持一致的事实 | 不应改变的内容／规则来源 |
| --- | --- | --- |
| 确认开始专注 | 新会话及一次参与；有兼容内容时的章节绑定与轮换位置 | 选择、取消、启动失败不生成这些事实；依RULE-START、RULE-SELECT |
| 暂停／继续 | 原会话状态、剩余量及原章落点 | 不新建参与、结束或额外所得；依RULE-PAUSE |
| 专注自然到期／确认结束 | 唯一终态与对应历史、本段真实故事结果；原段不再活动 | 手动只归档短章；自然到期按RULE-COLLECT判断完整章及生活收集。符合条件时终态与world_state一次提交，不生成待续事项 |
| 新建或修改想法、草稿保存 | 指定条目／草稿的合法版本、归属和输入状态 | 修改正式条目不新增身份，草稿不自动转正式；依RULE-NOTE、RULE-DRAFT |
| 收起、删除或有效撤销想法 | 指定条目的状态及必要删除／撤销依据 | 更新相关入口和适用计数，不改变原计时、故事或创建日；依RULE-UNDO |
| 收藏、取消或修改偏好 | 对应关系、已确认资格或偏好字段 | 不统一删除欢迎笺／已获内容，不收回故事事实；依A.4 |
| 替换备份／清空 | 经确认的整份新世代及其对象关系 | 不接受旧世代回执、输入或请求复活原数据；依C.7 |
| 查看、切模式、加载、读故事 | 仅查看或读取上下文 | 不产生业务记录；真实运行时间仍依原会话经过 |

联动不是同时写一份总计、一份图表和一份列表。先确认原事实变化，再让相关派生读取失效或重算；它们不成为第二套业务事实。重试、并发窗口和迟到回执不产生第二次结算，也不替其他对象清除待存状态。

<a id="command-db-contract"></a>

#### C.4.1 命令入口、修订与执行结果

同一操作只对原对象生效一次；重复点击或重试不能新建第二份记录。成功、确实无变化、冲突、失败和结果未知分别处理，旧结果不能覆盖更新事实。计时按原意图与真实截止点核对，撤销按实际执行时的资格判断。 执行细则见[C.9.12.1](06-data-commands.md#command-execution-detail)。

#### C.4.2 草稿、删除与故事检查点

明确保存才把对应草稿转成正式想法，保留原归属和创建事实；较晚输入不能被旧回执清掉。删除保护独立未交修改，不能复活已删目标。故事从同一入场依据与有效计时恢复，同一进展不重复记账，不可用内容不伪造落点。 执行细则见[C.9.12.2](06-data-commands.md#draft-checkpoint-detail)。

<a id="frontend-command-contract"></a>

#### C.4.3 前端意图、输入快照与在途协调

保存的是用户确认时眼前的输入；随后继续写的新字仍须保护。请求绑定原对象和来源，切页或关闭不能把它改派给新对象，也不代表已受理操作被撤销。同一对象的依赖操作按结果协调，其他可用阅读与导航保持可达。 执行细则见[C.9.12.3](06-data-commands.md#frontend-execution-detail)。

<a id="action-field-contract"></a>

#### C.4.4 动作、字段与状态的完整对应

每个动作均须说明前置状态、读取依据、允许改变什么、结果与返回；纯查看也要明确不写业务事实。失败与提交结果未知分开，重试先核对原操作。完整动作映射见[C.11](06-data-commands.md#action-field-matrix)，字段反向索引见[C.9.11](06-data-commands.md#field-reverse-index)；枚举中的候选不因此启用。 执行细则见[C.9.12.4](06-data-commands.md#action-execution-detail)。

<a id="data-quality"></a>

### C.5 读取、保存状态与冲突

**事实发生、输入是否提交、是否持久保存、读取是否完整，是不同问题。** 可恢复草稿可以已经保存，但仍不是正式想法；一段计时可以已经结束，但结束结果仍待保存。状态应对应对象、字段和范围，不用一个“正常／异常”遮住整页。

| 要辨认的状态 | 处理规则 |
| --- | --- |
| 待保存／失败／结果未知 | 保留本次结果、原可信内容及未交文字；未知先重读核对，不先报成功、移除内容或增加正式计数；进入休息也保留原段待存副本 |
| 仅本次可用／只读 | 说明关闭风险或写入限制，可信读取继续可用；只限制受影响动作，不冒充已存或新用户 |
| 未加载／部分可读／读取失败 | 标明对象和范围；仅在相应范围已核对时判断为空，不用初始数据覆盖原件 |
| 未知新版／损坏／无法安全并发 | 保护原件，进入必要的只读保护；不把失败当零记录或自行重建历史 |
| 另一窗口修改／删除同一目标 | 保留本页未交输入，先核对最新目标，允许明确重编或另存；不覆盖新版本、不复活已删条目、不自动改挂新会话 |
| 设备时钟变化 | 沿截止点核对，避免负数、重复结算或不可恢复状态；不承诺手动大幅改钟后的绝对精度 |

<a id="data-query"></a>

**查询契约。** 读取上下文须可区分数据世代／已提交修订、统计口径、明确窗口及相关时区；分页还须区分模式、边界与当前请求。一个窗口的汇总和趋势采用一致依据。迟到响应不覆盖新选择，关联想法不退回旧版本；游标失效时校核并重读受影响覆盖范围，以稳定ID去重、保留锚点，不用旧行号造成漏项或重复追加；现行页码接口及内部边界处理见[C.9.6.1](05-data-fields.md#record-read-contract)。

查询结果的完整性按所需字段与范围判断，不按屏幕已加载多少行判断。缓存可丢弃并重算，不进入个人历史或备份；无需强制每次全库扫描或一次渲染全部明细。数据库、索引与分页实现可变，但不能放宽身份、完整性与一致性要求。

**输入与内容语义。** 正式命令和导入均验证真实日期／时区、Unicode码点、明确枚举及内容schema；SQL类型、字符串形状或json_valid不能替代语义。普通入口不能传legacy、任意列或整份旧状态绕过约束。参照[执行约束](06-data-commands.md#execution-detail)的校核要求；逐秒帧、素材缓存和查看状态仍不成为新的业务写入。

**失败后的继续条件。** 待保存结果按原对象独立保护，不能被下一段覆盖。只有实现能保护原结果、隔离新旧操作并保持会话唯一性时，才开放受此影响的新计时；否则就近说明并仅限制相关启动，保留读取、恢复和离开入口。限制的是无法安全记录的操作，不是用户休息的资格；不以假称“已保存”换取流程继续。该条件须通过[T-FQ07](07-acceptance.md#t-fq07)验证。

**操作后呈现。** 数据确认后，相关入口和适用计数一致更新；失败保留原可信状态。页面输入、锚点、就近焦点及范围更新时机由[A.5.7](02-features.md#records-ui)维护，不能为保住画面继续显示虚假的运行、保存或对象状态。

<a id="recovery"></a>

### C.6 打开、重返与版本兼容

1. 先读本地数据及可用性。未知、损坏、只读、仅本次可用均有自己的技术状态，不能冒充新用户。
2. 有可信活动会话时优先恢复。暂停继续保持暂停；运行尚未到期则恢复真实剩余值；已过截止点只结算原段一次。专注显示本次恢复得出的静态结果，休息回专注准备，不补播或连开下一段。
3. 本次访问刚结束过会话，暂去记录或设置，再回来仍能辨认原结果；用户已明确进入下一段准备时保留该准备上下文，不重新弹回旧结果。冷启动若原段早已结算，读有效准备模式与真实历史；新会话成立后以新会话为准，旧段只在原记录回看。
4. 首次确认可用或成功清空后使用初始背景。老用户缺故事字段时保有计时、偏好及历史，仅新开始的相容会话绑定新章；关闭故事、减少动态或单幅图损坏不遮断可信计时。

应用从后台返回时保留当前页面、编辑面板和焦点。另一窗口已开始新段时，旧暂停、结束、撤销与重试不能作用于新段。**从备份恢复活动段不是上述普通重返：它按C.7作为暂停的原会话恢复。**

**版本兼容。** 数据格式、对象修订、数据世代和内容版本分别管理，不等同PRD或应用版本。旧素材可兼容映射；不能还原则保留可信摘要，不替换成新故事。已可靠收集的旧成果不追溯扣除；未知不补造。退役接续数据不再驱动新段，按C.9.7保留原件和可信历史，无法无损转换时提供只读／拒绝替换。

更新与重载仅在确认无活动会话、待存操作与未处理输入得到保护后进行，提交前再核对；用户可以稍后更新。数据不得假定平台必然永久保留本地存储。具体兼容映射须随实际数据和内容版本交付，不由本章指定技术栈。

<a id="backup"></a>

### C.7 备份、替换、删除与清空

**备份边界沿用P0完整JSON导出与替换恢复。** 导出某一一致时点可读、已提交的个人数据，覆盖已实现的偏好、活动与结束会话、参与、想法及可恢复草稿，以及已支持的故事检查点／终态／已收集事实／轮换、收藏与权益依据。可由可靠事实推得的值不必重复保存；临时浏览上下文、派生缓存、动画帧、图片与声音资源不是个人备份类别。未确认写入先提示并允许重试，不将本次副本伪称已进入备份。

生成文件与用户已将副本保存到外部是两件事；生成成功只能确认文件已生成。**便携备份策略：**删除标识保留，但`note_undo`短期撤销原文不导出，恢复后不复活删除内容、不续开撤销窗口；技术回执和派生缓存不导出。已提交草稿仍保护，不能与未保存输入混同。导入删除前的旧外部备份可能带回当时尚未删除的内容，预览须说明替换的是历史副本。细项与示例见[C.9.8](05-data-fields.md#database-backup)。

| 阶段 | 执行规则 |
| --- | --- |
| 导出含活动段 | 先核对到期；到期先结算一次。仍运行时捕获当时剩余毫秒，暂停时取已有剩余量；导出不打断本地会话 |
| 预览 | 校验格式、版本、类型、ID唯一性、引用、时间范围及活动段可解释性；展示双方记录数、草稿、将替换数据和活动段。损坏、未知新版或无法无损解释时阻止确认，保留原文件及当前数据 |
| 确认前保护 | 本机有活动会话时先由用户明确结束并可靠保存，允许导出本机副本后再替换／清空；说明刚保存的数据也将被替换。未交输入和待存结果不能被旧预览覆盖 |
| 执行替换 | 提交前重新核对世代、预览后变更及活动会话，有变化则重做预览。验证后的整份数据一次进入新世代，禁止先清空逐条写回；对象ID不重建，相同文件重复导入不新增业务事实 |
| 恢复备份中的活动段 | 恢复为暂停的原会话，保留ID、模式、目标、余量、开始时区、参与、原章／入场与本段检查点，连同已收集世界和轮换恢复。导出至导入时间不计投入，不重选章、不新增参与／收集。已结束小记不恢复为活动或待续；用户明确继续原活动段后才推进 |
| 取消／失败／结果未知 | 取消回原状态。只有验证原数据仍在或回滚成功，才可使用ERR09；结果不明先重读核对，再允许新的写操作 |

**恢复执行栅栏。** 预览计划固定文件摘要、本机世代／提交修订、运行时未交输入／待存版本和拟使用的新世代；取得写事务后再次核对。变化则重做预览，不依赖按钮先前已确认。原替换已提交、同计划回执丢失后再试，只确认已完成，不覆盖新世代内的新内容。当前参考格式按完整字段及真实JSON类型校验；未支持版本进入专门迁移，不能由数据库默认值补齐文件。详见[执行约束](06-data-commands.md#execution-detail)。

**文件与界面作用域。** 选文件、验证与预览绑定当前文件摘要、请求序号和面板作用域；更换文件或关闭后，迟到结果不重开预览或启用旧确认。导出须说明快照时点及仍未保护的输入，未存文字不冒称已在文件；外部保存取消不删本地也不报告外部已保存。清空与替换同样核对提交前的输入／待存及数据版本，提交后旧编辑器、旧自动保存和旧回调不能读取新epoch再次打包旧意图。实际多标签输入协调仍需适配器验证，单页守卫不能替代。

**删除与清空。** 单条想法删除及10分钟撤销依[RULE-UNDO](02-features.md#rule-undo)；删除事务将正式正文移入短期撤销区，成功撤销或到期清理移除该原文，正式历史只留必要删除标识。旧窗口的自动正文副本不得复活；独立未交修改按冲突规则保护并由用户明确另存。应用未运行时不承诺墙钟到点立即清除磁盘，但再次读取前先处理到期，不能继续提供过期撤销。取消收藏、隐藏展示分别依A.4。单条专注删除、改时长、补计时和备份合并仍未进入本期，不以“数据管理”新增权限。

清空全部须显示范围并再次确认：本机历史、参与、活动状态、设置、故事、权益／收藏、草稿及本应用保护的本地原文副本。成功进入首次准备及新世代，旧窗口丢弃待写内容；外部已下载副本仍由用户管理。缓存清理、卸载、取消收藏和清空不是同一动作；个人数据恢复也不等同商店购买权益恢复。逻辑删除不承诺取证级擦除或控制用户已下载的外部副本。

### C.8 本地资源与实现预算

<a id="story-storage"></a>

图、声音与版本化章稿随离线资源提供，个人数据仅保存正文、必要快照与用户事实。每段故事保存可还原当时结果的摘要，不复制整图、动画帧、指针轨迹或整部视频；当前生活使用有限槽位，重复使用不无限添物。正常绘制帧、时间跳秒、切页与普通查看不触发故事写入。

核心资源准备完成后可离线使用，资源提供方式由开发确定；锁屏提醒与计时恢复分别验收。容量不足时不能靠删除真实历史或已得成果换取通过。首轮目标沿用：每条历史的故事增量平均不超过128个UTF-8字节；以1,000／10,000段测编码、写入、恢复与手机响应，传输包体、资源缓存和个人记录分别测量，不根据理论配额许诺无限历史。具体成本与预算仍在[对应规格](12-stories.md#scene-cost)，这些数值是可复核的实现目标，不是产品永久原则。

实际引擎须交付等价身份、关系与提交边界、备份类别、合法缺失值及真实源版本迁移证据。故事128字节目标不含整库索引、撤销与操作回执，分别测量。验收见[数据闭环](07-acceptance.md#data-contract-tests)及[命令联动](07-acceptance.md#backend-db-tests)。
