### C.9 字段、关系与执行契约

#### C.9.1 设计范围与落地方式

**本版约定一个本地个人数据空间、明确关联的逻辑对象及可重算的派生结果。** 不建用户账号表、服务器行为仓库、每日成绩底表或一张独立的“记录页数据表”。一段会话一个身份、一次明确输入一个条目、一次真实发生的小事一个故事实例；不同页面访问这些对象，不复制数据。

逻辑字段、内容格式和动作映射在本附录定义；本版参考schema与便携format契约升为3，以区分已退役接续和新的收集边界。结构版本、对象修订、内容版本和备份版本独立管理；当前应用自己的snapshot版本不随本文自动更改。

生产数据库、物理表／集合／文件组织和适配方式由开发确定。本版13类有效逻辑对象与退役编号只供映射校核，不要求对应物理表数；开发须证明身份、关系、状态转换和原子提交。既有schema 2的SQL／机器清单属于旧参考，不能直接作为本版实现或验收证据。

**不采用两种极端。** 不把所有状态压成每秒重写的大JSON；也不按每个按钮或指标各建一表。设置／控制／草稿／世界等是有界小对象，不新建未完故事槽位。content_grants只承接已存在资格，不增加发奖机制；本期范围按5.1。

#### C.9.2 主外键与关系

| 关系 | 基数与约束 | 为什么这样组织 |
| --- | --- | --- |
| sessions → notes | 1对0..多；notes可以独立，所属新想法只指向focus | 找想法不复制会话；一段多条想法不能倍增时长 |
| sessions → session_stories | 1对0..1 | 普通计时、休息、无兼容章时可没有故事，不能伪造快照补齐 |
| story_items → session_stories | 当前规则1对1；同题材多次使用是不同实例 | 原段暂停／继续复用实例，新段不复用已结束实例 |
| story_continuation（退役） | 本版无运行时关系 | 旧格式存在此对象时走受控迁移，不把它重新接入新会话 |
| notes → note_drafts | draft为单例、edit时指向目标及基础版本 | 草稿可恢复，但不伪装正式想法，也不因目标删除自动另存 |
| notes → note_undo | 1对0..1；只对应当前删除版本和原撤销期限 | 删除原文短期隔离，不永久藏在故事/缓存/日志中 |
| world_state、story_rotation | 当前有界状态；绑定/结束的事务统一更新 | 当前布景不充当历史快照，轮换不当成奖励 |
| quote_favorites / content_grants | 按各自稳定内容ID去重，不混为一表 | “取消收藏”不能取消已有资格，欢迎笺不需要伪造收藏关系 |

素材目录、章稿与文案身份使用逻辑引用，不对缓存文件建立硬外键或级联删除。图没下载或旧资源退役时，仍可读取可信计时和快照摘要。`mutation_receipts`的目标是技术校核引用，不接受任意target_kind绕过专用命令。

**关联删除边界。** 删除便签、取消收藏或清缓存不得连带删除会话／故事。业务删除按对象语义执行；整份替换／清空在明确确认后原子完成，不向读取方暴露缺少关联的中间数据。参考DDL的RESTRICT是其中一种校核方式。

#### C.9.3 底表与字段字典

<a id="database-field-contract"></a>

##### C.9.3.0 共同定义、证据与阅读方式

本节定义13类有效逻辑对象的字段与一个退役对象编号，说明值域、产生依据、条件空值、修改权限、状态组合、备份与校验。生产实现须无损映射，不限定物理表或列数；真实内容字段与旧格式迁移须随实现交付。

**格式与实现分开。** TEXT／INTEGER、键和NULL用于表达逻辑契约，内部可采用等价结构。本版便携format 3须明确整数、0/1标志、NULL和JSON编码；旧format 2按其源规则解释，不能只替换版本数字。开发以映射与往返样例证明无损，物理结构与便携格式各自管理。

**字典的四个判断顺序。** 先查该行对象和所处状态，再查字段取值与NULL含义，再查谁能写/什么时候能改，最后检查关联对象和事务。不能只看某列在SQL里允许NULL，就认定所有状态都能留空；也不能只因SQL有DEFAULT，就在导入时填掉缺失数据。

| 约定 | 本版执行定义 |
| --- | --- |
| 类型与数值 | 业务底表/便携格式的INTEGER列必须是精确整数；0/1布尔不接受字符串或JSON true/false代替。整数及计算后落库结果须处于±(2^53−1)内；修订/计数另守非负或正值范围。小数、NaN、Infinity或溢出不得靠截断/强制转换修复。时间用UTC整数毫秒，分钟设置与毫秒目标明确换算。JSON子字段的数值另按内容schema定义。 |
| NULL与空串 | NULL只表示该列明确允许的“不适用、尚未发生或可靠旧信息未知”；三者依行状态辨认，不统一当0。0毫秒是可证实的实际0。`notes.body=''`是未删除的空记号；`notes.body=NULL`是删除标识，必须同时有删除依据。没有草稿时用无行，不插入一行全空占位。 |
| 身份与引用 | ID为非空、区分大小写、不含NUL的稳定文本，不裁剪、不转小写，不以时间/列表序号替代。新建前分配，重试沿用。ID只在其对象类型/数据世代内解释；在途键与回执匹配必须包含目标类型或对应的受控命令类型，不假定不同表同字符串指同一对象。 |
| 创建默认与导入 | 新库初值明确提供：25/5/15分钟、last_focus_min=NULL、声音0、应用减少动态0、场景/节点鼓励/纪念展示各1；不改变老用户偏好。其他事实、时间、ID和内容版本由真实动作/内容产生，没有“现在、空对象、零”默认。本版格式3的行字段须完整，NULL也显式出现；缺字段进入兼容处理，不使用SQL默认补文件。 |
| 字符与空白 | 正式小步骤≤80 Unicode码点，正式想法≤500；包括NUL在内均计码点，不按UTF-16单元/字节或用户感知字形计数。非法孤立代理码不进入规范UTF-8存储。正文不是自动trim后保存：只用统一空白集合判断“是否全空白”；有有效字符时保留原文，已有正文清空须确认后存空串。草稿保留超长/待修正输入，不先裁剪。 |
| 空白集合补明 | “去掉首尾空白后为空”采用固定集合：U+0009—000D、0020、00A0、1680、2000—200A、2028、2029、202F、205F、3000、FEFF；前端、命令、导入校验同口径。此定义不表示其余字符不能输入，也不自动删除正文空白。 |
| 对象修订 | 新对象row_revision=1；同一对象在一次提交中的内容有实际变化才+1，同值不UPDATE，不改业务版本。多个字段一起变化也只+1。删除草稿可是一笔有变化的事务，但正式正文没变时notes.row_revision仍不动。终态会话、终态故事等冻结对象不能靠递增修订绕过不可变要求。 |
| 四种版本 | row_revision管单对象竞争；data_epoch管整库替换；commit_seq管本世代一致读取；内容/状态/schema/format版本分别管解释边界。无业务变化的技术回执可令commit_seq增加，但不是用户新增一次参与。跨世代序号、输入序号、内容版本与对象版本不相互比较。 |
| 历史与正常入口 | `legacy`/`legacy_unknown`仅来自受控且有证据的旧数据兼容。旧信息未知不补造；缺某个字段只影响依赖它的指标。普通新建不能选择legacy绕过要求，编辑旧条目也不篡改来源。无法安全解释的输入保留原件并拒绝覆盖，不伪装空库。 |
| 责任边界 | 必须校验基础类型与身份、动作权限与前后状态、条件字段与版本、内容子字段，以及原子提交与一致读取。由哪层或哪种机制实现由开发确定；任一局部检查通过不能替代完整交互结果。 |

**备份标记。** P=已提交个人数据随便携备份保留；D=只导出必要源元数据，恢复另建本地控制值；X=不导出。字段表中的“初值”是受控新建的依据，不授权任何导入补缺。实现侧字段映射须与本字典逐项对应；本文的条件约束不能由SQL空值标识反推。

**兼容要求。** 结构版本相同不证明旧值满足当前语义；导入须核验真实源格式和字段含义，不能仅凭物理列未变就宣称兼容。

##### C.9.3.1 `db_meta`｜数据库控制信息

**权威写入方：**数据适配器。**备份：**D：只导出源版本/来源信息；恢复生成本地epoch和commit_seq，不整行覆盖。

| 字段 | 类型与值域 | 新建/NULL含义 | 产生与更新边界 | 关联/校验重点 |
| --- | --- | --- | --- | --- |
| `singleton` | INTEGER；整数，固定1；主键 | 建库显式1；不允许缺失/NULL | 数据适配器初始化；业务命令不可修改 | 一库恰有一行；不依赖自动行号 |
| `schema_version` | INTEGER；正整数；当前逻辑参考3 | 按实际适配声明版本；未知版本不得填3 | 仅受控结构迁移更新；与PRD版本独立 | 与实际结构及适配器支持清单一致；不是内容版本 |
| `data_epoch` | TEXT；非空稳定标识；区分大小写 | 建库生成；替换/清空生成新的本地值 | 数据适配器；普通命令只比较，不重写 | 备份源epoch仅溯源，不替代本地epoch；不是账号或权限令牌 |
| `commit_seq` | INTEGER；安全整数≥0 | 初始0；参考替换后1；不继承源序号 | 本世代每次实际写事务提交增1；回执/清理也可递增 | 新值≤2^53−1；同一事务校验业务行、回执及更新后的meta，溢出整笔回滚；不得自动换世代掩盖 |

**补明。** commit_seq只在同一个epoch内递增；初始化0、参考替换1不是历史参与次数。来源备份的版本/序号用于解释文件，不作为新库当前控制值。技术回执没有业务变化也可能增加提交序号。

#### C.9.4 数据不变量与操作校验

| 不变量 | 必须满足的数据约束 | 同一次原子提交必须校验的交互含义 |
| --- | --- | --- |
| 任一时刻至多一个活动会话 | 活动会话全局唯一，实现机制由开发确定 | 先核对到期与原对象，再接受新开始；不能只靠按钮禁用 |

#### C.9.5 提交协议与写入清单

命令字段与执行结果依[C.4.1](04-data.md#command-db-contract)。专用命令只接受注册参数；受影响行数、草稿归属与真实语义须在写事务内验证，不能由页面预先检查代替。

一次命令的顺序是：**开启原子写事务 → 核对世代 → 查原操作回执 → 核对对象修订与前置条件 → 写业务对象 → 校验跨表不变量 → 递增提交序号并记最小回执 → 提交成功 → 更新派生读取。** 回执、业务变更与提交序号必须一起提交。实际原子提交机制由开发确定；必须确认整笔业务结果，不能以其中一个字段或对象写入成功替代。

已完成的业务命令重试返回原完成依据，再读当前对象用于展示；不能把旧回执中的版本当作最新状态。相同op_id带不同参数要拒绝；相同对象版本被别窗修改时要冲突处理，不执行最后写入覆盖。创建类命令在重试前已分配稳定对象ID，不每次重试生成新ID。收据只保留去重所需元数据，不采用完整事件溯源；清理策略必须能证明不再接受旧命令，未证明时不任意按天删除。具体容量应和用户内容分别量测。

| 事件 | 原子写集合 | 提交后的读取影响 |
| --- | --- | --- |
| 开始专注 | sessions；必要偏好；合法故事的新story_items / session_stories / story_rotation；meta与回执 | 活动与参与读取；不创建待续，不改变已有收集 |
| 暂停/继续 | sessions及需要的本段story检查点；meta与回执 | 原段状态，不新增会话或参与 |
| 结束专注 | sessions、session_stories及story_items终态；符合RULE-COLLECT才写world_state；meta与回执 | 短章／完整章与实际时间一致；未确认写入保留待存，不提前显示收集成功 |
| 结束休息 | 以原会话ID提交终态、实际休息时长、归档日与已有活动 | 已存回忆进入时间流；专注时长、段数、参与和长休息节奏只读专注集合 |
| 保存新想法/修改 | notes；符合原草稿身份时清note_drafts；meta与回执 | 同ID多个入口和相关计数；不得清除别窗已新建的草稿 |
| 删除/有效撤销 | notes删除标识与正文、note_undo创建/移除，按冲突规则处理同目标草稿；meta与回执 | 正式想法集合、关联入口；不改sessions或故事 |
| 取消收藏/偏好 | 对应quote_favorites或app_preferences字段；meta与回执 | 对应关系或展示，不删除其他对象 |
| 替换/清空 | C.7指定类别按整份原子切换；新data_epoch，缓存与旧命令失效 | 同一已提交数据世代重新读取，不继承导入来源世代 |

若终态保存失败，不能在持久库仍有旧活动会话时再提交第二个活动会话。用户已有的本次临时结果/休息体验要保留并如实标明，恢复写入时先核对并原子处理原终态；不能用“先让界面好看”破坏活动唯一性。暂停、结束、返回前台、导出等时点根据真实时程求检查点，不每秒写库。

<a id="database-queries"></a>

#### C.9.6 读取、索引与指标来源

| 读取任务 | 权威来源／参考索引 | 关键边界 |
| --- | --- | --- |
| 正式计时/段数/结束分类与日趋势 | sessions → v_focus_ended；ended_focus_by_day | 同一日期范围、同一读事务；时长和未知缺口分别返回，不能SUM忽略NULL后宣称完整 |
| 参与与参与日 | sessions → v_focus_participations；focus_start_by_day | 只按已证实开始与参与日期，不从终态推回；未知分日另外说明 |
| 原会话的想法 | notes_by_session；同ID最新合法正文/删除标识 | 先按会话求时长，再关联便签；不可先做一对多联表再SUM |
| 想法倒序/更早一页 | visible_notes_by_time；(created_at_ms,note_id)游标 | 包含已收起，排除删除；未知日期旧内容单独可达，不冒充今天也不永久丢在分页之外 |
| 历史故事 | session_stories主键与stories_by_item | 前者找当次快照，后者只解释同一事项多段关系，不把多段计时合并 |
| 收藏 | visible_favorites_by_time | 不联入欢迎笺/权益凑“收藏次数” |
| 撤销到期清理 | undo_by_expiry | 开启、相关操作、导出前先清已到期原文；应用未运行无法保证墙钟到点立即执行物理清理，但再读取前不可暴露过期原文 |

读取按本节语义由开发选择索引与存储方案。默认经历流的合并排序键为日期、事件时刻、类型和稳定ID；类型只用于同刻确定性排序，不形成等级。现行界面使用明确页码与前后页；内部可用游标、页边界缓存或等价实现，不能把行号当对象身份。月份与想法包含查询已定，标签、分词／模糊查询和复杂筛选另行评审。

查询上下文含data_epoch、已提交修订、指标口径版本、窗口、模式与边界。相同窗口的指标/趋势在同一一致读取中产生；分页之间修订变化时，验证并重新读取受影响覆盖范围，以ID去重、保留阅读锚点，再推进游标。不能靠前一次offset假定新插入的旧日期想法不会漏读。缓存只可重算，不是备份必需项；本期不以日统计表作为唯一权威源。若未来为了性能物化汇总，须声明推导版本、失效/重建方法和与底表对账，不反过来覆盖底表。

<a id="record-read-contract"></a>

##### C.9.6.1 查找、综合场景与物件来由的逻辑格式

**沿用事实，不建第二套收藏库。** sessions负责计时，session_stories负责本段过程与历史，world_state负责初始／已收集生活。收集随符合条件的到期终态事务提交，物件来由及索引由其原会话与目录派生，不写quote_favorites，不新增物件背包或获得计数。

| 对象／字段 | 逻辑格式与依据 | 保存／兼容边界 |
| --- | --- | --- |
| 纪念小画与来源 | 从已保存的专注或休息取会话ID和当时活动，按活动关联小画，按会话定位单次经历 | 小画索引可重算；活动资料缺失时保留该段可证实的时间事实。见[记录呈现](02-features.md#records-modes) |
| 综合场景资源 | 稳定world_key，首版一项；标题、构图版本、固定区域及day／night背景光线资源引用 | 版本化本地资源；两种呈现共用物件定义与几何布局，不复制个人世界数据 |
| 物件定义 `object_key` | 非空稳定字符串；名称、区域／占位、初始是否存在、合法状态、各状态静态资源、组合表现 | 资源目录声明；同件重复使用不换ID，不从标题或图片猜身份；无图提供文字 |
| 物件变化与来源映射 | 冻结版本的完整结果条件与object_key映射 | 登记事实键、类型、初值、缺失含义和收集条件；当前状态读world_state，来源读符合条件的会话终态；活动检查点不证明已收集 |
| 物件小话资源／临时选择 | `(object_key, state_key, copy_version)`对应1—3条短句，当前object_key、条目序号与请求身份 | 文案随资源交付；状态须可信。选择／轮换游标仅本次访问，不进世界状态或备份，旧结果不覆盖新物件 |
| 初始／已发生／来源未知 | 初始属性来自资源配置；故事变化须有已存事实依据；无法追溯来源不填假日期 | 不单独创建获得日志。来源查询可建可重算索引，既有事实不因索引／资源缺失被删除 |
| 昼夜预览 | `day`／`night`；首次按本地时段，后按本次选择 | 临时显示上下文，不写world_state、偏好或备份，不作为故事节点条件 |
| 月份条件 | `all`、`YYYY-MM`或独立`unknown`范围 | 当前模式的临时条件；查询固定归档日／想法创建日，不改旧日期键 |
| 想法查询 | 已提交Unicode文本；比较副本做NFC、去查询首尾Unicode空白、ASCII英文字母大小写折叠、连续子串包含 | 正文原件不变；标点／百分号等按字面，不作正则／通配。空词不筛正文，不保存查询历史 |
| 分页请求／结果 | 模式／子视图、月份、查询词、object_key（适用时）、page_number（从1起）、page_size=20、data_epoch／读取修订、稳定边界与请求身份；结果含目标页条目、同条件total_count（未知为NULL）、has_previous／has_next及完整性／错误范围 | 页面只展示当前一页；总页数从可信total_count推导，空结果无第1／0页。逻辑页码不等于可移动行号身份，不强制OFFSET或一次加载所有明细；缓存可丢弃重算 |
| 阅读返回上下文 | 来源模式、有效条件、页码、读取版本、对象ID／日期与相对位置；生活场景再含昼夜选择、object_key或故事ID | 仅当前访问保留，替换／失效后校核，不跨世代用旧行号定位 |

**物件与来源查询。** 小屋读取可信初始／已收集world_state及目录；列表区分初始布景、当前规则收集和有据旧成果。来由覆盖全量相关已结束会话，每页20条，不只看已加载记录。未收集的小记在“回看故事”可达，但不成为物件获得来源。旧成果有据而来源不明时如实说明；图片或活动节点不能证明获得。

**写入与恢复。** 本段节点只更新session_stories检查点；符合收集条件的到期事务统一写终态与world_state，重试沿原ID。打开小屋、切昼夜和读来由无业务写入。新事实键须在[C.9.3.10](#content-json-contract)登记类型、状态、迁移与备份；显示选择及派生索引不备份。旧映射不能解释时保留可信摘要／原件，不清库或补造收集。

**查询一致性。** 想法搜索含已收起、排除删除／草稿；全日期查询也包含日期不详的可信正文，选月则与该月取交集。查询、正文、世界状态或世代变化后校核成员与游标，按稳定ID去重并重读受影响范围；迟到响应不盖新条件。读取失败不能返回“0条且完整”。实现可选择扫描、索引、缓存或虚拟化，必须验证相同可见结果与返回路径。

真实物件字段和节点由已审核章稿注册；定义资源格式不代表生产内容已完成。验证见[T-REC26—39](07-acceptance.md#record-scale-tests)。

<a id="database-migration"></a>

#### C.9.7 旧数据映射与版本迁移

按“读原件 → 识别实际格式 → 制作字段映射 → 在隔离候选库转换 → 结构/语义/数量与时长校核 → 原子切换”的顺序交付。不能将新建空库DDL直接执行到用户旧库，也不能先清旧库再逐条导入。

活动对象、参与记录和结束记录只有在原会话身份或其他明确依据相同时，才合并到sessions同一行；不按相同时间/相同时长猜测是同一段。旧记录能证明结束但不能证明开始时，has_start_fact不补1；能证明开始但终态未知时用legacy_unknown，不能恢复成正在运行。只有可靠历史源键缺少新ID时，才使用稳定映射分配新ID并记录迁移对应，不生成虚假的开始时间。

旧归属、结束原因、时区或时长未知保留NULL/unknown。真实旧接续仅作为旧格式输入：保留来源历史与已知进度的可解释摘要，不再供新段接入；旧活动会话仍须恢复同一会话，不能冒充已结束。已可靠收集的旧成果不追溯扣除，不将旧短章自动补为完整章。没有可核验无损映射时，中止替换并保留原件／只读访问；普通新建命令不得用legacy绕过检查。

兼容性清单应随实际源版本提供；本版没有真实旧库字节的迁移样本，因此不交付声称可直接升级现有应用的迁移脚本。备份格式版本、数据库schema版本、内容版本和对象修订各自独立。

<a id="database-backup"></a>

#### C.9.8 备份、临时原文与清空边界

导出规则：**便携备份保留已提交的个人事实和可恢复草稿，不导出note_undo短期撤销正文、技术回执或派生缓存。** 删除标识保留，恢复后不得复活删除内容，也不重新开启10分钟撤销窗口；恢复到删除之前用户自行保留的外部备份，仍可能带回当时尚未删除的内容，导入预览应说明这是历史副本替换，不声称能控制外部文件。

| 类别 | 便携备份／替换原则 |
| --- | --- |
| app_preferences、sessions、notes、note_drafts | 包含已提交且声明支持的字段；草稿不转正式；删除想法的body保持NULL |
| story_items、session_stories、world_state、story_rotation | 保存同一时点的关联与版本；活动段导出可信本段检查点；不导出新的待续槽位；已结束短章不因导入获得收集 |
| quote_favorites、实际已有content_grants | 保留文本快照与已有资格；不从次数补造尚未交付的奖励 |
| db_meta | 导出解释格式所需版本与源快照信息；源epoch仅为来源元数据，导入另建本地epoch；不复制源commit_seq充当本地当前修订 |
| note_undo、mutation_receipts、UI/查询缓存、包内素材 | 不导出；旧窗命令在新世代失效，图片等按资源机制提供 |

便携数据声明格式名及版本；本版逻辑契约schema_version=3、format_version=3，生产实现须提供实际格式映射。源格式1／2及其他版本必须有可核验转换，不能只改版本号或用SQL默认值补齐。导出前核对真实到期；未到期段仅在备份内转暂停，不改本机运行。重复导入不新增参与、收集或故事；导入的活动段由用户明确继续，未完成小记不变成待续。

对已删除条目，自动缓存/快照中不能永久藏有一份正文；story快照不得嵌便签。与目标相同但没有独立未交修改的草稿副本应清理；用户在别窗确有未交输入时按冲突规则保护供明确另存，不自动恢复已删目标。清空全部覆盖草稿、撤销原文、关系标识、操作回执与本应用保管的迁移副本；外部文件由用户控制。数据库逻辑删除不宣称取证级擦除、系统备份删除或加密；如需此类承诺须另做平台安全设计。

#### C.9.9 实现交付门槛与实测范围

交付前必须同时具备：实际引擎的底表/对象存储映射、等价约束与事务边界、源版本迁移映射、读写失败/并发/恢复验证、数据量样本，以及正确的隐私说明。运行时间、节点映射、用户输入和原子提交分别验证；静态表结构无法证明这些体验已成立。

实际应用需验证手机、多窗口、存储中断、旧库迁移、内容映射和用户路径。涉及故事的暂停、结束与导出使用真实内容计算器，不以示例数据代替。见[数据验收](07-acceptance.md#data-contract-tests)与[命令联动验收](07-acceptance.md#backend-db-tests)。
