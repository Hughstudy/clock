# 语言创作经验手册

> [返回语言学习地图](README.md) · [研究基础](01-foundations.md) · [当前语气规则](../../prd/08-voice.md)
> 2026-11-23。本页以项目返工与编辑复盘为依据；不是经过用户实验验证的评分量表。

## 1 先记住这几次返工

| 遇到的问题 | 当时容易采取的做法 | 后续暴露的原因 | 更可复用的处理 |
| --- | --- | --- | --- |
| 句子不自然、重复 | 把177条运行资源精简为61条 | 总体更干净，开始专注却只剩5条；日常趣味也被削薄 | 单句去坏处，同时检查各高频入口的容量与题材；不能只优化全库数量 |
| “好”字开头太多 | 换成大量“我喜欢”“我有时” | 换开头后，意思与语气仍很相似 | 合读连续十条，检查说了什么、怎样说、落在哪里三个层面 |
| 想写得友好 | 每句都允许、安慰、解释不完美 | 用户仿佛一直有问题需要被照顾；人物像温柔的指导者 | 普通快乐、口味、发现和小得意也能独立存在 |
| 想表现轻微笨拙 | 每件事都做错，再说没关系 | 角色变成反复失败或索取安慰的人 | 它也会熟练、顺手、成功；少量失误由它自己自然处理 |
| 想增加情绪价值 | 给点击开始赋予勇敢、自律等评价 | App知道的是操作，不知道用户动机、困难和实际产出 | 确认发生的事；具体求助才给相应建议 |
| 想让故事有意义 | 最后补一个总结或用户建议 | 每段重新变成相同的道理，读者没空间体会 | 删除最后一句试读；故事本身成立就停在那里 |
| 想显得有自己的生活 | 写“刚才我做完了”“你不在时我……” | 容易误称未展示、未保存的后台事件 | 一般偏好或独立虚构往事可以；当下行为与共同历史必须有真实依据 |
| 想实现长期新鲜 | 大量随机、稀有度、连续剧情 | 把用户吸引到不断查看，或增加漏看压力 | 维持直接随机与可忽略；好玩之外同时检查是否影响用户的事 |

这些是本项目的具体经验，不扩成所有产品都必须遵守的通则。177与61包含当时不同状态的素材，原始计数见[逐句记录](../../prd/24-copy-review.md)；260是后续工作稿，不是上线数量。

## 2 写一句话之前，先填最少的信息

| 项目 | 要写清什么 | 例子 |
| --- | --- | --- |
| 出现时机 | 哪个真实动作／哪个主动类别 | 用户主动点了通用鼓励 |
| 用户正在做的事 | 此时主要任务与可用注意力 | 愿意打开阅读；计时仍可能进行 |
| 这句独立带来什么 | 一个回应、偏好、观察、趣事或建议 | 角色对一本书插图的奇怪好奇 |
| 说话依据 | 实际状态、用户主动选择、一般习惯或虚构往事 | 角色过去的独立趣事，不含共同记忆 |
| 显示条件 | 是否需要时间、活动、任务等已知事实 | 没有特定活动要求；不声称此刻翻书 |
| 忽略后会怎样 | 不读是否仍能继续用户任务 | 不漏结果、不丢机会、不需补剧情 |

一句话可以同时有两种作用，但不要为了填满表格额外加句子。题材、句式、长短属于编辑维度，不新增运行时人格或用户情绪标签。

## 3 三种审稿尺度

**单句看是否成立。** 它有没有说App不知道的事？建议需要用户补多少前提？角色像在自然说话，还是作者借它表达理念？笑点需要新动画才能看懂吗？“今日”“刚才”“又一次”“记得你”有没有事实依据？

**同入口合读十条。** 圈出反复出现的意思和结尾。十条都可以安静，也可以其中几条活泼；不按比例强制交替。检查是否总用同一种转折：弄错了→也不错，做得少→也算，累了→允许歇。语义相近的两句未必都删，但要有不同的适用价值。

**放进实际路径。** 进入→开始→中断→回来→结束→休息，每个节点分别看固定状态和角色话语。避免连续三条建议、刚开工又教开工、保存失败还讲故事、还没读完就换句。显示寿命、正文阅读与隐藏开关沿用已有产品机制。

词频和相似度检查可用来找候选问题，不能自动决定好坏。“我喜欢”可以好听，“好，开工”也可以自然。删除高频词不是写作目标。

## 4 把同一题材写出不同内容

以下是原创练习，供比较写作意图，不直接加入运行库。

| 意图 | 例句 | 为什么不是只换词 |
| --- | --- | --- |
| 个人口味 | 点心有脆边的话，我会先挑那一块。 | 明确偏爱，没有把用户拉进道理 |
| 一点得意 | 我找书签挺快的。因为每本书里都夹了一张。 | 普通小办法，不需要失败或修复 |
| 小发现 | 同一杯茶，第一口和最后一口，我常常更喜欢后面那口。 | 感官偏好，可接出不同话题；不是功能建议 |
| 轻微笨拙 | 有回画杯子，画得像土豆。我给土豆加了个把手。 | 失误后有自己的选择，停在趣事上 |
| 独立兴趣 | 一本书的故事还没看懂，我倒先认出了画插图的人。 | 关注点有自己的次序；不用解释“各有节奏” |
| 平常亲近 | 来啦。见到你真好。 | 只是欢迎，不设置答复义务 |

先找到内容，再考虑表达形式。不能把一个茶故事改成咖啡、牛奶、汤就计为四份独立创意；也不需要为追求差异让人物每次偏好相反。

## 5 关系感怎样留在有限交互里

最有用的亲近常常很普通：来时欢迎，想做事时不缠着，用户主动找它时有内容可听，结束时态度仍然自然。点了休息，不自动解释成疲惫；连续使用，不自动说“我们已经越来越亲密”。

它可以有自己的判断，例如偏爱脆边、喜欢某种摆法，也可以改主意。意见主要落在它自己的生活与选择上；不靠反驳用户、评价用户任务或拒绝用户正常操作证明“不讨好”。

通用入口可分享一个完整小故事。具体求助入口先接住那个需求，再看个人经验是否有帮助。例如用户主动选“被打断”，书签的经验可能贴题；此时随机讲挑点心的故事，可能显得没回应。

## 6 留给实际使用的检查

纸面编辑只能筛掉明显问题。试用时分别问：这句当时是否合适；有没有一句愿意再听；哪句像在教我或猜我的心情；是否影响开始或回到自己的事；关掉文字后是否仍然完整好用。

愿意看更多，不自动等于更适合番茄钟；快速离开，也可能说明用户顺利去做自己的事。先使用自愿反馈与现有流程观察，不为评估新增隐性情绪记录、私密便签分析或持续行为追踪。详细证据与评估边界见[长期使用研究](04-familiarity-and-variety.md)。
