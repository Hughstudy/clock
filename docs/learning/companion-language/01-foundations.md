## 1 这次究竟要解决什么

用户指出：61句不足以支撑每天使用、持续两个月的体验；同题材和开头重复；希望至少200句真实素材，重点投入开始专注、不同时间开始、进入和休息，允许中长句、两句话的小故事和轻松近况。希望使用后感到舒服，可能是开心，也可能是平静，随机带来一点小惊喜。随后明确要求先学习好的心理对话，以及咨询、社会、市场和消费心理学。

上一轮把“不打扰、自然、不重复”过度理解成压短与删减。这会消除明显坏句，却也把人物的兴趣、选择和日常趣味一起削薄。200句是内容容量的下限；每次遇见是否有不同的意思、是否合时宜，才是需要解决的体验问题。

**状态：** 本次文档发布基于 `30087b117c2d84d49ddbb6db2cc82a36a420941c`，线上仍为61句。工作区已形成260句扩写稿和条件选句实验，尚未发布，也不视为完成审稿。本文样句同样是候选，不替换09的现行原文。没有做两个月用户研究，没有验证这些文字对ADHD、焦虑或治疗的效果。

## 2 六个方向分别学什么

这些领域有交叉，不能简单分成六套独立话术。以下只选与番茄钟的具体问题有关的材料，不以理论数量代表研究质量。

| 方向 | 本次读到的依据 | 对本产品的推论 | 不能直接推出什么 |
| --- | --- | --- | --- |
| 咨询心理学 | 动机式访谈训练强调有依据的肯定、倾听和允许修正理解；焦点解决示范从具体例外中寻找可行线索。[S1—S3] | 先回应用户实际表达或操作；用户主动求助时，给一个够具体的起点 | 固定句库不是咨询；不能靠点击推断深层情绪，也不能照搬需要连续作答的咨询过程 |
| 社会与关系心理学 | 关系回应研究关注对方是否感到被理解、被重视和被关心，而非说话者自认有善意。[S4] | 用户想休息时，能顺利休息，比不断声明“我尊重你”更有说服力；关系通过反复可靠的相处成立 | 真人关系研究不证明虚拟角色能替代真人关系；也不支持凭使用天数自动升级亲密程度 |
| 动机与自我对待 | 自主、胜任与联结是自我决定理论的重要概念；自我关怀实验提示，接纳不足并不必然降低改进意愿。[S5—S6] | 支持行动和允许停下可以同时成立；不把亲近当成完成任务的奖品 | 不是一概不能表扬，也不是每次都让用户选更多选项；实验结果不等于本App疗效 |
| 消费心理学 | Redden研究区分了真实刺激与人们感到的重复，具体差异的可辨认性会影响厌倦。[S7] | 编辑时检查用户能否感受到内容差别；不能用换茶、换书、换纸船掩盖同一道理 | 不能从食品等实验算出本产品最佳句数；贴题材标签不自动带来新鲜感 |
| 市场与传播心理学 | 广告重复研究区分表面变化和实质内容变化，其效果受参与程度和重复次数影响。[S8] | 既检查措辞，也检查说话目的、内容和落点；稳定的人物声音与变化的内容需要一起维护 | 不能把广告说服效果当作陪伴舒适度；不据此设置稀有台词、限时关心或回访压力 |
| 情绪与认知心理学 | 情绪模型区分愉快程度与唤醒程度；W3C补充指南强调减少不必要中断及交给用户控制。[S9—S10] | 平静、轻松、轻微好奇和开心都能成为目标；让内容丰富，让展示克制 | 不代表所有ADHD用户只喜欢短句，也不代表焦虑用户只能接收安慰；没有统一的“舒服文案” |

这些依据支持提出设计假设。某句是否好听、好笑、耐看，仍需编辑判断和实际使用反馈，不能在台词后贴一个理论名字就宣布有效。

## 3 从具体示范对话里学到的分寸

以下为对原材料的简短意译与分析，不是逐字翻译，也不是本App可直接播放的对话。

### 3.1 接住对方实际说出的内容

MIA:STEP的基础示范中，对方不想说话时，回应先承认当下不想开口，不急着追问原因。另一段带评分的示范中，当事人讲孩子对自己的重要性，回应沿着这个明确表达继续，而非凭空判断她的内心。[S1，印刷页68、169—170]

**迁移到App：** 用户点击开始，只能证明计时开始；不能自动推导“你终于战胜拖延”。选择“难开始”可以成为提供起步建议的依据，却仍不证明原因是完美主义、害怕失败或懒惰。

候选对照：

| 实际情境 | 不采用的写法 | 更合适的候选 | 原因 |
| --- | --- | --- | --- |
| 用户刚开始计时 | “你终于愿意迈出勇敢的一步了。” | “开工。咱们各忙各的。” | 操作得到回应，不被赋予陌生的人格评价 |
| 用户主动选择难开始 | “我知道你是怕做不好。” | “如果还不知道从哪儿下手，先把要用的东西打开。” | 给可执行的建议，保留原因未知 |
| 用户结束了计时 | “虽然没坚持完，你也很棒。” | “这段就到这里。” | 不凭空设立失败，再给予补偿性夸奖 |

### 3.2 温柔也需要事实依据

SAMHSA的指南把肯定与泛泛表扬区分开，并要求在更深入的反映之后观察对方回应、修正理解。[S2] 这是固定句库缺少的能力：它无法靠一条台词完成真正的倾听与核实。

**迁移到App：** 可以说“见到你，我挺高兴的”，这是角色的当下态度；“我懂你这一路多不容易”需要并不存在的信息。用户没有表达难受时，也不先给他安排一个需要安慰的位置。

### 3.3 从抽象要求退回一个具体线索

SFBTA手册的一段母女示范，从“总不交流”的概括，找到上周一次谈科学项目的经历，继续确认那次交流有哪些不同。[S3，Dialogue #4，印刷页21—22]

**迁移到App：** 语言可以把建议缩到可辨认的动作，例如找回打开的那一页。它不能据此宣称用户已经形成某种习惯；也不应在启动时追问一连串“成功例外”，把专注入口变成咨询作业。

咨询材料最值得学的是回应依据、节奏和尊重。人物仍然可以平常、幽默、有自己的话题，不必始终保持咨询腔。

## 4 回头检查61句与260句工作稿

检查对象为已发布资源及2026-11-23工作稿，计数单位是一条完整素材，标点不另算一句。下表是容量比较，不是质量评分。

| 入口 | 已发布 | 扩写工作稿 | 主要判断 |
| --- | ---: | ---: | --- |
| 再次进入 RET | 5 | 24 | 需要普通招呼、亲近和少量趣味，不能每次都提问 |
| 开始专注 STA | 5 | 96 | 最值得投入；须区别刚开始的回应、自己的偏好及少量轻故事 |
| 开始休息 BRK | 6 | 48 | 增加闲适和好玩，减少换着说“休息也可以” |
| 非零结束 END | 4 | 24 | 真实收束与亲近，不假设任务完成 |
| 零时结束 ZER | 2 | 4 | 简单确认足够，没必要凑一个庞大故事池 |
| 主动请求，四类 ASK | 39 | 64 | 可容纳较完整的回应；具体求助类别先回应请求 |
| 合计 | 61 | 260 | 尚未定稿，删除与改写后仍须满足至少200条可用素材 |

工作稿减少了“好”开头，却出现新的惯性：31条含“我喜欢”，47条含“小”，60条含“先”。这些数字只提示合读检查，不能据此机械禁词。更重要的问题是：书、纸、积木虽然轮流出现，很多段落仍在表达“做一点也好”“不完美也行”。

例如，把纸船折歪、杯子画歪、积木搭矮，都写成接纳不完美，用户可能感到的是同一段说教。三件事应该有不同的看点：一次是误打误撞，一次是坚持自己的审美，一次是实用的小发现。也允许其中一件只是没成功，人物自然地换个做法，不必每次得到漂亮结论。

## 5 重新确定写法

### 5.1 让舒服有多种样子

这是一组创作目标，不是对用户情绪的自动分类。人物可以让人觉得省心、受到欢迎、愿意动一下、轻轻笑一下，或者对一件普通东西起了点兴趣。默认不需要每次更兴奋，也不把平静写成寡淡。

温暖可以直说。轻松可以来自一句干脆的回应。好玩可以来自人物认真对待一件无关紧要的事。故事不必在最后把这件小事解释成人生哲理。

### 5.2 人物的偏好要通过选择出现

“我喜欢有趣的小东西”信息很少；“杯子带把手的那边，我总觉得才是正面”能让人看见它的观察习惯。后者只是一个候选例子，不应接着扩成几十个“我觉得……很像……”模板。

保留几个能记住的倾向：喜欢琢磨形状和颜色、对小尝试有兴致、稍微笨拙但不反复自贬。题材可跨读书、茶、植物、食物、纸和声音；性格不随随机结果改变。不要把“爱人般照顾”缩成大量亲昵称呼，或要求用户给角色回应。

### 5.3 自动出现与主动阅读承担不同的内容

| 使用时刻 | 内容承担的任务 | 合适的形式 | 不合适的做法 |
| --- | --- | --- | --- |
| 再次进入准备页 | 欢迎见面，留出选择空间 | 平常招呼、短偏好、偶尔一件独立趣事 | 连续追问近况、责怪缺席、要求回应 |
| 刚开始专注 | 顺畅进入用户要做的事，带一点人物气息 | 简洁回应、一个清楚的小观察；不需要每条都一样短 | 计时已经开始却布置新的自省任务；长故事要求读完 |
| 专注进行中 | 保持可用和安静 | 现有状态与动作；主动点开才继续阅读 | 为展示200句而增加定时插话 |
| 开始休息 | 允许注意力自然松开 | 闲话、轻趣味、自己的偏好，偶尔实用建议 | 把喝水、伸展、呼吸列成必须完成的休息清单 |
| 主动找伙伴说一句 | 回应本次愿意听的内容 | 通用类可有完整小故事；具体求助类先给贴题回应 | 因为故事有趣而绕开用户选择的需求 |
| 结束、错误、保存 | 清楚可靠地收束或处理问题 | 事实明确，关系语气稳定 | 用笑话覆盖错误；把到时等同现实任务完成 |

当前自动话语会随专注界面退让；较长内容需核对既有全文入口。不能为了容纳新故事，默默延长驻留、抢焦点或新增面板。主动阅读没有自动超时，适合承载两句话以上的完整表达。丰富度与打断频率分别设计。

### 5.4 不让每句话都变成支持技术

普通招呼、个人口味、小得意、无伤大雅的笨拙、本身有意思的观察，都可以成立。不是每句都要“赋能”“接纳”“鼓励行动”。一个相处舒服的角色，应有日常话题，不能把用户始终放在被分析、被修复的位置。

这也不意味着全部删除建议。用户明确选择“难开始”“被打断”“有点累”时，具体帮助可能正合需要。关键是情境，而非机械禁止祈使句或表扬。

## 6 试写：先比较味道，不直接加入运行库

下列均为原创候选。涉及往事的文字属于角色虚构回忆，不代表后台真实活动、共享前情或已获得收藏物；无需当前画面重演。各条独立成立，不随机拼接。

| 候选场景 | 台词 | 想试出的味道／条件 |
| --- | --- | --- |
| 再次进入 | 来啦。见到你真好。 | 直接的亲近，不夹带任务 |
| 再次进入 | 正好碰个面。接下来各自忙，也算一起。 | 并肩感，语气可以普通 |
| 开始专注 | 开工。咱们各忙各的。 | 干脆，不先假设困难 |
| 开始专注 | 这一会儿，我陪你。 | 少量熟悉话保留位置，不强求新奇 |
| 开始专注／短偏好 | 杯子带把手的那边，我总觉得才是正面。 | 一个容易理解的小观察；审稿时防止同句式成批复制 |
| 开始专注／短故事 | 有回画杯子，画得像土豆。我给土豆加了个把手。 | 两句完整趣事；不再补“所以不完美也很好” |
| 已知晨间开始 | 早上好，开工啦。 | 普通招呼也有价值；只在设备本地时间确为晨间时适用 |
| 已知短段开始 | 短短一段，开始。 | 不把短时长夸成意志胜利，也不假定只能做一个开头 |
| 开始休息 | 歇会儿。我对这项安排很满意。 | 有自己的态度，轻松但不判用户表现 |
| 开始休息 | 什么都不安排的几分钟，我也挺喜欢。 | 偏好，避免说成用户必须学会放空 |
| 开始休息／偏好 | 点心有脆边的话，我会先挑那一块。 | 具体口味，没有教育落点；不是宣称此刻吃点心 |
| 开始休息／短故事 | 我看过一朵像面包的云。看久了，又觉得像馒头。 | 简单轻趣味，接受有人觉得普通 |
| 主动通用／稍长故事 | 有回想学一段曲子，后半段总哼错。后来原曲再响起来，我还愣了一下：怎么跟我会的不一样。 | 轻微笨拙与小反转；不要求新增音效或演奏动画 |
| 主动通用／稍长故事 | 有张纸颜色太好看，我一直没舍得折。后来只折了一个角，发现背面也好看。这下更舍不得了。 | 人物有点纠结，却不是等待用户拯救；不安排下次续集 |
| 主动通用／个人见闻 | 我试过按颜色整理东西。看着很整齐，找起来又是另一回事。 | 小发现，不强行解释成用户的方法论 |
| 主动难开始 | 如果还不知道从哪儿下手，先把要用的东西打开。 | 一个具体动作；不凭空判断困难原因 |
| 主动被打断 | 先看看刚才停在哪儿。找到那一页、那一行，再往下接。 | 适合阅读或文字任务；正式入库须有任务适用依据，当前先留候选 |
| 主动疲惫 | 歇会儿吧。这次休息，也可以不安排别的事。 | 接住请求，不要求做好休息 |
| 结束计时 | 这段就到这里。 | 清楚收束，手动与自然结束都成立 |
| 结束计时 | 和你一起待了会儿，我挺高兴。 | 关系落点不取决于效率或时长；零时池不采用 |

这些候选不是“已经更受欢迎”的证据。有些刻意普通，有些带一点怪趣味。下一次合读应检查它们与整个句库的关系，而非只挑单条最漂亮的。

## 7 两个月视角：总量与遇见次数分开算

如果每天重新打开一次，在同一个入口独立、等概率抽取一次，60天内不同素材数量的期望为：

`N × (1 − (1 − 1/N)^60)`

| 同一情境下的合格候选数 N | 60次抽取预计遇见的不同素材 |
| ---: | ---: |
| 5，当前开始专注池 | 约5条 |
| 6，当前开始休息池 | 约6条 |
| 24 | 约22.1条 |
| 69，工作稿中一个固定时段、时长与可见活动组合的开始池示例 | 约40.3条 |
| 96，仅作无条件可抽满96条的对照 | 约44.8条 |

69的工作稿示例来自60条通用、4条匹配时段、4条匹配时长和1条匹配活动。96是全部开始素材，不是同一用户每次都可抽的数量；260更不能当作开始入口的池大小。

上述只是概率模型，不是实际用户体验测试；假设每天一次独立抽取，未模拟同次打开内的相邻避重、内容被降噪挡住、用户没看见、一天多次或日程变化。它说明扩充有帮助，也说明随机不会自动保证60天不重复。不同句子仍可能有同一个意思；熟悉的喜欢台词再次出现，也不必一概认作失败。

保持用户已选定的直接随机：每次打开取得新随机种子，合法池内抽取，运行内仅排除各池上句。不因研究厌倦而偷偷改回顺序轮播、洗牌袋或必须读完整组。

## 8 三种内容组织方法的取舍

| 方法 | 收益 | 两个月后的风险 | 本轮取舍 |
| --- | --- | --- | --- |
| 各入口统一扩成大池，主要改句式 | 实现简单，字面重复减少 | 高频入口仍可能被低频素材稀释；同一情绪落点反复出现 | 容量可以扩，不能作为完整写作方案 |
| 按天解锁连续生活日记 | 连贯，容易形成期待 | 缺席产生补课感；时间与事件真实性难守；要求新叙事状态 | 暂不引入，与简单交互和用户自由相处方向不合 |
| 高频入口多投入，独立趣事与日常回应并存，以真实条件筛选 | 允许随机相遇，无须追剧情；性格可以稳定而内容丰富 | 有条件句的可见率需核对；仍会重复，需要内容编辑 | 推荐继续打磨；份额通过素材配置实现，不添加隐藏情绪画像或强制语义轮换 |

长期吸引力不能全部交给不断新增句子。保留能记住的口味、说话节奏和相处方式，让人逐渐认出这个角色，和让人偶尔听到新事同样重要。这是产品判断，尚待真实使用检验。

| 检查角度 | 已发现的问题 | 具体修正 |
| --- | --- | --- |
| 从高频使用检查容量 | 61句中大部分在主动入口，开始只有5句 | 至少200条实际可用素材；开始与休息合计优先获得超过一半创作投入，最终比例再按试稿调整 |
| 用咨询示范检查回应 | 泛化夸奖和猜心理，看似温柔却可能不贴题 | 把事实、主动选择、虚构角色偏好分别写清；不知用户心情时不装作知道 |
| 把所有故事合读 | 换道具后仍反复讲“不完美也可以” | 去掉结尾道理，让选择、失误、观察本身有看点；补普通快乐，而非继续加安慰 |
| 放回真实操作检查 | 开始后教学、长话与界面退让争注意力 | 先回应动作；长内容优先主动阅读；不新增定时插话与强制停留 |
| 从60次相遇检查重复 | 素材总量被误当作单入口可见量 | 用合法池与展示路径评估；概率、语义和可见性分别检查 |
| 用反例检查原则 | 过度避评价、避长句、避建议，会再次删成寡淡 | 不设机械禁词；用户主动需要建议时给建议，普通好话可保留，篇幅依场景而定 |

**最强的反对意见：** 用户打开番茄钟是要做自己的事，可能根本不想读角色故事。这个意见成立。丰富素材应提高愿意读时的体验，不要求每次读，也不把隐藏、关闭或快速离开视为失败。另一面，用户明确要求有趣，不能用“保护注意力”把人物重新写回只有几句允许与安慰。

下一轮逐句审稿使用四个问题：这句此刻成立吗；它带来什么独立内容；它像这个角色自然会说的吗；看过十次仍不讨厌吗。最后一个只能先作编辑预判，不冒充用户验证。测试时应同时问喜欢什么、哪里别扭，以及是否干扰开始任务，不只统计点击和停留。
